# fixtures/ — 녹화 픽스처

구 엔진에서 채록한 요청/응답 시퀀스가 여기 쌓인다. **attended 녹화 런(C1)의
산출물**이므로 이 디렉터리는 M1 자동 실행 중에는 비어 있는 것이 정상이다.

## 커밋 조건 (하드 게이트 4)

여기 들어오는 모든 파일은 채록기의 **마스킹 검사기를 통과한 것만**이다:
자격증명·호스트·접속정보·실데이터 패턴이 0이어야 한다. 실데이터 도구
(`GetSqlQuery`·`GetTableContents`)의 픽스처는 **데모 테이블만** 사용한다.

검사를 통과하지 못한 채록물은 저장 자체가 거부된다 — 손으로 넣지 말 것.

## `attended-only/` — 재생할 수 없는 픽스처

`replay-attended.mjs`는 **이 디렉터리 바로 아래의 `*.json`만** 수집한다
(`readdirSync` 비재귀). 하위 폴더는 기본 재생에서 빠진다.

`Create*` 계열 픽스처가 여기 산다. 재생은 신 엔진이 같은 질문을 SAP에 **다시
던지는** 일이라, 생성 시퀀스는 두 번째 실행에서 "이미 있다"로 실패한다 — 신
엔진이 옳아도 실패한다(`scenarios/README.md` 함정 ⑶). M1 19종에 `Delete*`가
없어 러너가 스스로 되돌릴 방법도 없다.

**왜 그냥 두면 안 되는가 (실측)**: `zsapkit-m1-program-create`를 기본 재생에
남겨 두고 돌렸더니, 그 시퀀스의 실패가 **`GetProgram`의 증거까지 앗아갔다** —
다른 시퀀스에서 통과한 도구인데 커버리지 표가 "증거 없음"으로 떨어뜨렸다.
재생 불가 픽스처 한 건이 표 전체의 판독을 망친다.

**그래서 `Create*`의 증거 급은 `replay`가 아니라 `attended`(대표 건 실기)다.**
여기 있는 픽스처는 그 실기가 실제로 일어났다는 **기록**이고, 재생 자산이 아니다.
다시 재생하려면 사람이 SE38·ADT로 대상을 지운 뒤 `--fixture`로 명시해야 한다.
