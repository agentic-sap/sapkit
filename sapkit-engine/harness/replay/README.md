# replay/ — 재생 러너 · 의도적 차이 목록 · 커버리지 표

픽스처를 신 엔진에 **같은 순서로** 먹이고 정규화 후 diff 0인지 판정한다.
증거를 **만드는** 쪽은 `harness/recorder/`이고, 여기는 **"같은가?"를 판정하는**
쪽이다.

## 세 경로

| 경로 | 언제 | 단계 판정 |
|---|---|---|
| 통과 | 정규화 후 동일 | `match` |
| 불일치 | 다른데 등재가 없다 | `mismatch` — **결함** |
| allowlist | 다른데 등재가 있다 | 대체 기대 시험이 판정 |

allowlist 갈래는 다시 셋으로 갈린다.

| 단계 판정 | 뜻 |
|---|---|
| `allowlisted-pass` | 대체 기대 시험이 "신 엔진 쪽이 옳다"를 증명했다 |
| `allowlisted-fail` | 등재는 됐지만 신 엔진이 기대한 대로 동작하지 않았다 |
| `allowlisted-deferred` | 대체 기대 시험을 다른 작업이 소유한다 — **통과가 아니라 무증거** |

시퀀스 판정은 `pass` / `fail` / `no-evidence` 셋이다. 이연이 하나라도 있으면
실패가 없어도 `no-evidence`다 — 비교에서 빼는 것이 곧 무증거가 되지 않게 하는
것이 장부 등재 규칙 ②이기 때문이다.

## 등재는 **차이가 났을 때만** 발동한다

장부가 말하는 "등재 항목만 동등성 비교에서 제외된다"는 *그 차이를* 제외한다는
뜻이지, 그 도구의 모든 단계를 대조 밖에 두라는 뜻이 아니다. 그래서 같으면 그냥
통과이고, 다를 때 비로소 등재를 찾는다. **등재가 없으면 결함이다.**

**휴면 항목은 차이를 면제하지 않는다.** 휴면인데 차이가 났다면 그 도구가 이미
존재한다는 뜻이고, 장부가 낡았다는 신호다. 조용히 통과시키면 그 신호가 사라진다.
그런 단계는 `mismatch`로 남되 어느 항목이 휴면인지 `detail`에 적는다.

## 무엇을 비교하지 않는가

| 자리 | 왜 |
|---|---|
| `/recordedAt` | 채록의 출처이지 엔진이 낸 응답이 아니다. 정본은 채록기의 `REPLAY_METADATA_POINTERS`이고 `comparableFixture()`가 그 투영을 준다. 살아 있는 쪽에는 **이번 재생 시각**이 들어가므로 두 값은 실제로 다르다 |
| `/engine` | 신 엔진은 이름부터 다르다(`mcp-abap-adt` → `sapkit-engine`). 같기를 요구하면 모든 재생이 실패한다. `provenanceDifferences`로 **출처로 보고**하되 결함으로 세지 않는다 |
| `/placeholders` | 정규화기가 단계를 훑어 만든 **파생 요약**이다. 단계가 모두 같으면 여기도 같을 수밖에 없어 판정에 다시 세우면 같은 결함을 두 번 세고, 등재된 차이를 면제할 길이 막힌다. 보고에는 남긴다 |

그 밖의 새 필드가 생기면 `sequenceDifferences`에 떨어져 **실패한다** — 형식이
늘었는데 대조가 따라가지 못한 것을 조용히 넘기지 않기 위해서다.

## 상관 보존 — 자리표시자 되묶기

픽스처에 원본 토큰은 없다. 1단계가 받은 잠금 핸들은 `<<LOCK_HANDLE_1>>`이고
2단계 인자에도 같은 자리표시자가 있다. 그대로 보내면 신 엔진은 존재하지 않는
핸들을 받는다.

그래서 재생은 살아 있는 쪽에서 자리표시자를 다시 묶는다 — 방금 받은 응답을
**채록기의 정규화기로** 정규화하고, 원본과 정규화 결과를 나란히 걸어
`자리표시자 → 이번 판의 원본 토큰`을 읽은 뒤, 다음 단계 인자에서 되돌린다
(`rebind.ts`). 정규화 **규칙을 다시 구현하지 않는다** — 결과를 원본과 대조해
관찰할 뿐이다. 규칙이 두 벌이 되는 순간 대조가 의미를 잃는다.

**한계**: 인자 자체에서 처음 생긴 자리표시자(사람이 넘긴 타임스탬프 등)는 원본이
픽스처 어디에도 없다. 정규화는 되돌릴 수 있는 규칙이 아니라 판정용 사상이기
때문이다. 그런 자리는 자리표시자 그대로 나가고 **`notes`에 남는다** — 조용히
넘어가지 않는다.

## 오류 응답의 대조 (장부 D13)

오류 문구를 통째로 무시하지 않는다. 넷으로 쪼갠다.

| 조각 | 대조 |
|---|---|
| `sapText` — SAP이 돌려준 메시지 · 구 엔진이 조립해 실어 보내던 계약성 문구 | **엄격** |
| `codes` — `ERR_*` · `[AdtType]` · `(kind)` · JSON-RPC 코드 | **엄격** |
| `statuses` — HTTP 상태 | **엄격** |
| `prose` — 나머지, 곧 엔진이 스스로 지어낸 진단 산문 | 정규화(느슨) |

느슨하게 판정한 건은 `proseNormalized`에 담기고 **커버리지 표가 센다**. 조용히
넘어가면 오류 경로 전체가 무증거가 된다.

**엄격 신호가 하나도 없으면 통과시키지 않는다.** "산문**만** 다르다"는 말은
엄격한 부분이 있고 그것이 같을 때만 성립한다. 양쪽 다 코드도 상태도 SAP 텍스트도
없는데 문구가 다르면 그것은 *아무것도 대조하지 못한 것*이므로 `error-prose`로
떨어뜨리고, 의도된 차이라면 장부에 등재하게 한다(그 실례가 D18이다).

> **C1에서 손볼 자리.** `sapText` 규칙은 지금 둘뿐이다 — `Z… error (…): …` 꼴의
> 계약 문구와 ADT 예외 XML의 `<message>`. 구 엔진이 SAP 메시지를 **이미 조립된
> 산문 안에** 실어 보내는 모양이 녹화에서 관찰되면, 그 모양을 잡는 규칙을
> `ErrorSignatureRules.sapText`로 더해야 한다. 지금 추측해서 넓히지 않은 이유는
> 구 형식을 손에 넣기 전이기 때문이고, 좁아서 놓치면 `error-prose`로 떨어져
> **눈에 띈다**(넓어서 삼키면 눈에 띄지 않는다).

## 보고서는 새지 않는다

픽스처 쪽(`expected`)은 마스킹 검사기를 이미 통과했으므로 그대로 실을 수 있다.
신 엔진 쪽(`actual`)은 **방금 살아 있는 시스템에서 온 값**이라 그렇지 않다.
그래서 채록기의 `scanForSecrets`를 한 번 지나고, 걸리면 규칙 id만 남긴
`<<REDACTED: …>>`로 대체한다. 걸린 원문은 어디에도 남기지 않는다.

## 의도적 차이 목록 (`divergences.ts`)

사람용 정본은 `harness/DIVERGENCES.md`다. 이 파일은 그 문서 중 **재생 대조가
판정에 실제로 써야 하는 것**만 옮긴 것이고, 어긋나면 문서가 이긴다.

| # | 상태 | 도구 | 여기 실린 이유 |
|---|---|---|---|
| D1 | 활성 | `GetSqlQuery` | spec §2.4 사전 등재. 대체 기대 시험은 실데이터 도구 작업이 소유 → **이연** |
| D2 | 휴면 | `UpdateLocalTypes` | 사전 등재. 도구가 M1 밖 |
| D3 | 휴면 | `GetIncludesList` | 사전 등재. 도구가 M1 밖 |
| D13 | 활성 | — | 오류 대조 **규칙**. 단계 면제가 아니라 비교 방식이라 `applies`가 null 이고, 발동 건수를 커버리지 표가 센다 |
| D18 | 활성 | — | 무접속 거부 어휘. 장부가 "기계가 소비하므로 따로 둔다"고 적었다 |

**D4~D12 · D14~D17을 옮기지 않은 이유**: 접속·기동·프로파일 계층의 차이라 도구
응답 시퀀스에 나타나지 않는다. 각 항목이 장부에 자기 대체 기대 시험의 자리를
적고 있다. D7은 장부가 **명시적으로** "복원이므로 재생 대조에서 제외 대상이
아니다"라고 적었고, D8은 축소분이라 판정 자리가 C1 녹화 관찰이다.

### 장부에 항목이 늘 때 여기 무엇을 적는가

```ts
{
  id: 'D19',
  title: '한 줄 요약',
  tool: 'UpdateClass' | null,          // 계층 차이면 null
  classification: '수리' | '강화' | '축소',
  status: 'active' | 'dormant',
  evidence: '근거 문서 경로',            // 등재 규칙 ① — 비면 거부된다
  substituteTest: '대체 기대 시험의 소재', // 규칙 ② — 축소만 null 허용
  resolvesIn: '해소·활성화 마일스톤',      // 규칙 ④ — 축소·휴면이면 필수
  applies: (step) => step.tool === 'UpdateClass',  // 어떤 단계에 걸리는가
  check: ({ recorded, actual }) => ({ ok, detail }), // null이면 이연
}
```

`assertLedgerWellFormed()`가 규칙 ①②④와 id 중복을 강제한다. 이연된 항목에
나중에 검사를 물릴 때는 `withSubstituteChecks(M1_DIVERGENCES, { D1: fn })`.

## 커버리지 표 (`coverage.ts`)

`buildCoverage()`가 **기계가 읽는** `CoverageReport`(그대로 JSON이 된다)를 내고,
`renderCoverageMarkdown()`이 **사람이 읽는** 마크다운을 낸다. 파일로 쓰지 않는다 —
어디에 쓸지는 부르는 쪽(자체 게이트·attended 재생 스크립트)이 정한다.

증거 급은 spec §2.5의 셋이다: `replay`(녹화-재생 대조) · `contract`(도구별 계약
시험) · `attended`(대표 건 실기). "전 표면 공통"(tool-catalog 대조 · 게이트 ·
마일스톤별 attended 확인)은 도구 단위가 아니라 표면 전체에 걸리므로 이 표의 행이
아니고 자체 게이트가 소유한다.

표가 드러내야 하는 것:

- `toolsWithoutEvidence` — **어느 급에서도 통과 증거가 없는 도구**. 마크다운이
  전용 절로 따로 적는다. 이 목록이 표의 존재 이유다.
- 휴면 등재 — 장부 표에 `**휴면**(활성화 자리)`으로 적히고 `passed`가 0이다.
- 이연 등재 — `deferred`로 세고 **통과로 세지 않는다**.
- 산문 정규화 건수(D13) — 총계와 도구별, 그리고 그중 **엄격 신호가 하나도
  없었던 건수**까지.

도구 이름은 `loadM1ToolNames()`가 `harness/old-surface/m1-tools.json`에서 읽는다.
여기 베끼지 않는다 — 그 파일이 구 엔진의 실측 기록이고, 두 벌이 되는 순간 어느
쪽이 정본인지 알 수 없어진다.

## 재생 대상

`ReplayTarget`은 채록기의 전송 계약(`열기 · 도구 호출 · 닫기`)과 **같은 모양**이다.
일부러 그렇게 뒀다 — 가짜 전송을 시험에서 그대로 쓸 수 있고, 신 엔진도 같은
구멍에 꽂힌다.

| 구현 | 쓰임 |
|---|---|
| `InProcessTarget` | 신 엔진을 `createServerCore` + SDK `InMemoryTransport`로 **같은 프로세스 안에** 세운다. 규약은 진짜로 태우되 프로세스는 늘지 않는다 |
| `ScriptedTransport` (채록기) | 단위 시험. **프로세스 0개** |

신 엔진을 자식 프로세스로 띄우지 않는 이유는 이 머신에서 jest가 자식 프로세스
수거에서 비결정적으로 블록된 실측 기록이 있기 때문이다(`HANDOFF.md`).

## 쓰는 법

```ts
import { InProcessTarget, buildCoverage, loadM1ToolNames, renderCoverageMarkdown, replaySequence } from './harness/replay';
import { parseFixture } from './harness/recorder';

const fixture = parseFixture(fs.readFileSync('harness/fixtures/demo.json', 'utf8'));
const result = await replaySequence(fixture, new InProcessTarget({ startup }));

const report = buildCoverage({ tools: loadM1ToolNames(), replays: [result] });
console.log(renderCoverageMarkdown(report));
```

## 지금은 픽스처가 없다

실제 녹화(C1)는 소유자가 SAP에 접속해 수행하는 **attended 단계**이고 아직 하지
않았다. 그래서 이 디렉터리의 시험은 전부 **합성 픽스처**로 돈다 —
`fixtures/`에는 아무것도 쓰지 않는다. 실녹화 대조는 C1 뒤에 합친다.
