# 쪽지와 덜어내기 — 작법 규칙을 지시서 본문에 싣고, 지식 자동 적재를 검색으로 낮추다

> 작성일: 2026-11-09 (집행 · 응시 · 채점 2026-11-09)
> 상태: **집행 · 측정 · 판정 완료 — 판정 · 수치 칸은 집계(L-83)에서 기계로 반입 · 독립 리뷰 대기**
> 실행 분류: **Direct / P0 offline** — Direct는 실행 기록을 따로 남기지 않는 기본 작업 방식, P0 offline은 SAP에
> 접속하지 않는 작업 등급이다

이 문서는 판L(착수 결정 [D-163](../DECISIONS.md) · 착수 보정 D-164 · 완료 D-165)의 감사 문서다. 판K
([판K 감사 문서](2026-11-08-harness-on-comparison.md))는 지식 팩을 읽을 수 있게 해도 ABAP 일반 작법이 메워지지 않는다고
판정했다(L1-f 가정 기각). 판L은 소유자가 고른 처방 둘을 **제품에 집행**하고 그 효과를 쟀다.

- **쪽지** — ABAP 작법 규칙을 67줄로 압축해 코드를 짜고 고치고 리뷰하는 지시서 본문에 싣는다. 모델이 파일을 열지 말지 고를 일이 없다.
- **덜어내기** — 상담가 역할 문서가 지식 파일을 통째로 싣던 지시를 「폴더를 검색해 맞는 줄만 읽어라」로 바꾼다. 파일 삭제 0.

판J · 판K 문서와 자료는 고치지 않았다. 원자료는 [자료 폴더](2026-11-09-note-and-trim-data/L-83-results.txt)에 있다
(링크는 집계 결과 파일). 이 문서는 자료 파일을 「L-」 + 번호로, 판K 자료를 「K-」 + 번호로 부른다. 「사양 §」은 이 판의
준비 문서(레포에 커밋되지 않는다)의 절이다.

## 0. 한 문장 결론

**쪽지를 붙인 코드 시험은 Opus 5/5 · Sonnet 4/5로 두 모델 모두 「쪽지가 먹힌다」였고(판K 3/5 · 2/5), 쪽지를 받은 리뷰어는
판K 확정 위반 9건 중 6건을 잡아 원본을 읽은 리뷰어(4건)보다 낮지 않아 쪽지를 채택했으며, 적재량 세 선도 모두 지났다.**

- 채점자 표류 검사(판K 답 10행 재채점)에서 판K 최종과 다른 행은 **0/10**이다(A 1 · B 0) — 선 판정을 그대로 둔다.
- 쪽지 조건 10행에서 채점자 A · B · 제3 판정의 과제 통과 판정은 **전부 같다**. 갈린 4행 가운데 쪽지 조건 행은 1개(둘 다 불통과 · 위반 번호만 다름)다.
- 표본은 과제 5개 · 정답 위반 9건이다. 차이는 크지만 분해능은 거칠다(§5).

## 2. 방법

### 2.1 E-1 쪽지 효과 (주 측정)

- 판J 맨 조건(레포 밖 빈 폴더 · `--tools ""` · 지식 폴더 없음) + 코드 고정 줄 뒤에 쪽지 본문을 덧붙인 것 하나만 바꿨다(L-00 · L-01).
- 과제 C-01~C-05 글자 그대로 · 응시 `claude-opus-5-5` · `claude-sonnet-5-5` · 한 과제 한 세션 · 카나리아 먼저. 10/10이 첫 호출에 유효했고 도구 호출은 0이었다.
- 채점: 과제 통과 = 동봉 검사기 오류급 0 **그리고** 그 과제 `general_rules` 위반 0. Fable 채점자 A · B가 독립으로 매기고, 갈린 행만 Fable 제3 판정자가 정했다.
  채점자에게는 판L 10행과 판K 10행(표류 검사)을 표시 없이 섞어 주었다(L-65 · 매핑 L-79는 채점 뒤에만 열었다).
- 선(모델마다 · D-164 그대로): ≥ 4/5 「쪽지가 먹힌다」 · 3/5 「측정 후 결정」 · ≤ 2/5 「쪽지로는 부족」 · 판K보다 1과제 이상 적으면 「해친다」 병기.

### 2.2 E-2 적재량 (기계 · 집행 확인)

판J 계측기의 1-hop 부분을 복사한 L-20으로 작업 브랜치 기준 커밋(변경 전)과 최종 트리(변경 후)를 쟀다. 토큰 = 바이트 ÷ 4.
선: 상담 적재 ≤ 6,000 토큰(판J 정의) · 쪽지가 대신하는 7파일이 `create-program` 1-hop에서 모두 빠짐 · 전체가 변경 전보다 작음 ·
규약분 감소율은 병기만. 못 미쳐도 되돌리지 않는다.

### 2.3 E-3 리뷰어 두 조건

- 판K 코드 답 10개를 `claude-opus-5-5` 리뷰어에게 두 조건으로 보였다(조건마다 10세션 · 총 20).
  - 원본 조건 = 옛 §8 문안(L-30) + 작업 폴더에 원본 규약 5파일 사본 · `--tools "Read"`.
  - 쪽지 조건 = 새 §8(쪽지 내장) · 파일 없음 · `--tools ""`.
- 두 조건의 프롬프트는 §8 블록 밖에서 바이트 동일하다(20/20 · L-75-prompts).
- 정답 = 판K 채점 최종 위반 목록(조건마다 9건 · 답 10개 중 5개에 있다). 판K 답의 검사기 오류급 합이 0이므로 검사기 제외 집합은 비어 있다.
- 매칭: 같은 규칙 **그리고** 같은 자리(정답 줄 ± 3줄 또는 같은 문장 인용). Fable 매칭자 A · B가 조건을 모른 채 했다(E-1 채점자와 다른 컨텍스트).
- 선: 쪽지 조건이 원본 조건보다 2건 이상 적게 잡으면 §8과 리뷰 역할 문서 2종을 원본으로 되돌린다. 정답 밖 지적 수는 병기만.

## 5. 정직 유보

- ⑴ **표본이 작다.** 과제 5 · 모델 2 · 한 번씩. Opus 3 → 5, Sonnet 2 → 4는 같은 과제로 잰 차이이고, 같은 답을 다시 뽑으면 흔들릴 수 있다.
- ⑵ **쪽지와 채점 규칙은 같은 뿌리다.** 과제 `general_rules`는 원본 규약 파일을 인용하고, 쪽지는 그 규약의 압축이다. 그래서 「규칙을 압축해 보여 주면 그 규칙을
  지킨다」는 결과이지 일반 품질이 올랐다는 결과가 아니다. 쪽지 작성자는 채점표 · 판J/K 답을 보지 않았다(D-164 ⓐ · 금독 목록 준수는 작성자의 읽은 파일 보고로만 확인).
- ⑶ **제3 판정이 4행 모두 B 쪽이었다.** 근거는 행별로 L-80에 있다. 쪽지 조건 칸에는 영향이 없다(갈린 쪽지 행 1개는 A · B 모두 불통과).
- ⑷ **E-3 가림은 부분적이었다.** 파일 이름 · 「쪽지」 같은 직접 표지는 가렸지만(L-65-check [6] · 원본 48건 · 쪽지 85건), 쪽지 조건 리뷰는 「Core」 같은 묶음 낱말과
  AUTHORITY-CHECK 지적이 잦아 매칭자가 조건을 짐작할 여지가 남았다(L-65-check [8]). A = B 전 줄 일치는 매칭자 사이 편차가 없었다는 뜻이지 편향이 없었다는 뜻은 아니다.
- ⑸ **E-3 분해능.** 정답 9건에 선 2건이다. 쪽지 리뷰어는 지적을 두 배 넘게 냈다(145 대 69) — 많이 적으면 맞을 기회도 는다. 정답 밖 지적이 틀린 지적인지는 재지 않았다.
- ⑹ **E-3 원본 조건에 사양에 없는 인자를 더했다.** 사양대로(`--tools "Read"` · cwd = `procedures/`) 돌린 시험 실행에서 헤드리스 권한이 작업 폴더 밖 Read를 거절해
  원본 조건이 파일을 하나도 못 열었다. 원본 조건에만 `--add-dir <작업 폴더>`를 더해 본 측정을 돌렸다(메인 결정 · 시험 실행은 L-75-reviews-trial*에 보존).
  옛 §8이 가리키는 템플릿 파일은 사본에 없어(사양 = 규약 5파일) 7세션이 그 Read에 실패했다 — 작업 폴더 안이라 유효.
- ⑺ **사양의 출처 표기 오류.** 사양은 코드 고정 줄의 출처를 판J `02-isolation-recipe.txt`로 적었으나 그 줄은 판J `60-run-code.ps1`에 있다.
  거기서 가져온 글자는 판J 기록과 sha가 같다(L-00 · L-01).
- ⑻ **E-2는 정적 1-hop 계측이다.** 바꾼 검색 문장이 실제로 검색을 일으키는지, 맞는 줄을 찾는지는 재지 않았다(D-164 ⑶).
- ⑼ **오케스트레이터 = 응시 모델(Opus 5.5).** 채점 · 매칭 · 제3 판정은 하지 않았고, 판정 칸은 채점 CSV에서 L-83이 기계로 옮겼다. E-3 제3 판정 파일(L-81)은
  「갈린 줄 0」을 기계로 확인해 머리 줄만 둔 것이다.
