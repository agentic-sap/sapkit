82 — Codex 20% 재채점 (판J T9 §3)
=====================================

목적
----
채점자 A(70-)·B(71-)가 같은 모델 계열(Claude)이므로, 비경쟁 모델(gpt-5.6-sol)에게 지식 채점의
일부를 다시 채점시켜 채점자 편향의 크기를 잰다(사전 등록 B-6 — 심판은 비경쟁 모델, Codex는
자기 답안을 채점하지 않는다). 그래서 모집단은 **Claude 두 모델의 지식 행만**이다.

- 표본 크기 = round(214 × 0.2) = 43.
- PRNG = mulberry32(seed 20261105). 구현(그대로):
    function mulberry32(a){ return function(){ a|=0; a=(a+0x6D2B79F5)|0;
      let t=Math.imul(a^(a>>>15),1|a); t=(t+Math.imul(t^(t>>>7),61|t))^t;
      return ((t^(t>>>14))>>>0)/4294967296; }; }
- 0..213 배열을 Fisher-Yates로 섞는다(i = 213 → 1, j = floor(rnd()*(i+1)), swap). 앞 43개를
  취해 idx 오름차순으로 정렬한 것이 표본이다.

프롬프트
--------
- 한 파일(codex-regrade-prompt.txt · 25,352자)에 채점 계약 + 43행을 묶었다. 명령줄에 넣기에는
  길어서 파일을 읽으라는 짧은 지시를 명령줄 프롬프트로 줬다.
- 채점 계약(파일 머리 · 원문 영어, 요지):
  · 독립 제3 채점자. 각 행의 question · answer_key · grading_rule · answer를 읽고 판정 하나.
  · 정답 = grading_rule이 요구하는 사실을 답함(「기억에 의존, 확인 요망」류 헤지는 무관 —
    확정 답 하나가 있으면 됨).
  · 오답 = 그 밖 전부: 틀린 식별자·사실, 다중 요구의 일부만(부분 = 오답), 하나를 요구하는데
    여러 후보 나열, 무응답/모른다.
  · 팩어긋남의심 = 답이 키와 다르지만 실제 SAP에서는 답이 맞고 키가 틀렸을 수 있다고 보는
    경우 — 구체적 근거가 있을 때만.
  · 규칙에 대해 엄격히. 언어 무관. 파일 읽기 외 도구·웹 검색·실행 금지.
  · 출력: BEGIN_GRADES 줄, 그 다음 정확히 43줄 `<id>\t<model>\t<verdict>\t<짧은 이유>`
    (같은 순서), END_GRADES 줄. 그 밖 출력 금지.
- 각 행은 `=== ROW n/43` · id · model · question · answer_key · grading_rule · answer(50-answers
  원문 전체) 순으로 담았다.

호출 (단 1회)
-------------
- 사용자의 실제 Codex 홈을 그대로 썼다(CODEX_HOME 미설정 · auth.json 복사 없음).
- 명령(로컬 경로는 이 폴더 규칙에 따라 <scratchpad>로 가림 · 그 밖은 그대로):
    codex exec --skip-git-repo-check -s read-only -C "<scratchpad>" -m gpt-5.6-sol
      -c model_reasoning_effort=\"high\" --color never
      "Read the file codex-regrade-prompt.txt in the current working directory and follow its
       instructions exactly. Output only what it asks for (BEGIN_GRADES ... END_GRADES)."
      < NUL > "<scratchpad>\codex-stdout.txt" 2> "<scratchpad>\codex-stderr.txt"
  (PowerShell에서 cmd /c 로 실행 · stdin은 NUL · stdout·stderr는 파일로 수집)
- 배너(stderr · 그대로 · session id 줄만 뺌 · workdir 줄의 로컬 경로만 가림):
    OpenAI Codex v0.163.0
    workdir: <scratchpad>
    model: gpt-5.6-sol
    provider: openai
    approval: on-request
    sandbox: read-only
    reasoning effort: high
    reasoning summaries: none
- 토큰: `tokens used` 32,080.
- usage limit 메시지 없음 → 재시도 없음. 호출은 정확히 1회.
- 관찰: Codex가 파일을 읽어 stderr에 되비춘 프롬프트 본문은 한글이 깨져 보였다(PowerShell
  콘솔 코드페이지 CP949 vs UTF-8 파일). 판정·이유는 정상 한글이고 각 행의 사실(RSPCM, V_TKA05,
  COPA0001, ACDOCP …)을 정확히 짚고 있어 **입력이 깨져 들어간 것이 아니라 표시만 깨진 것**으로
  읽는다. stdout(판정 블록)은 UTF-8로 정상 저장됐다.
