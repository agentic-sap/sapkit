# 하네스를 켠 비교 — 지식 팩을 읽을 수 있으면 맨 모델의 빈틈이 메워지는가

> 실행 분류: **Direct / P0 offline** — Direct는 실행 기록을 따로 남기지 않는 기본 작업 방식, P0 offline은 SAP에

이 문서는 판K(착수 결정 [D-160](../DECISIONS.md))의 감사 문서다. 판J([판J 감사 문서](2026-11-05-harness-necessity-review.md) ·

「유지」 처방이 기대는 가정 하나 — 「지금 하네스가 그 빈틈을 메운다」 — 를 재지 않은 채 남겼다. 이 판은 판J와 **같은 지식
표본 60 · 같은 코드 5과제**를 **하네스 폴더(지식 팩 + 페르소나)를 읽을 수 있는 조건**(이하 「켠 조건」)으로 다시 응시해
판J 결과와 견줬다. 판J 문서와 자료는 고치지 않았다. 제품 파일(`interactive/` · `sapkit-engine/` · `sapkit-cli/`)은 한
바이트도 바뀌지 않았다.

원자료는 [자료 폴더](2026-11-08-harness-on-comparison-data/README.txt)에 있다. 이 문서는 자료 파일을 「K-」 + 번호(예: K-00)로,
판J 자료 파일을 「J-」 + 번호로, 판J 감사 문서의 절을 「판J 문서 §」로 부른다. 「K-00 §1」은 그 파일 안의 절이다.
「사양 §」은 이 판의 준비 문서(레포에 커밋되지 않는다)의 절이다.

## 0. 한 문장 결론

**하네스 폴더(지식 팩 + 페르소나)를 읽을 수 있게 한 Claude 두 모델의 층 판정은 L1-a(모듈) 측정 후 결정 · L2(페르소나) 측정 후 결정 · L1-f(ABAP 일반 작법) 가정 기각이고, 세 모델 모두를 요구하는 D-160의 문언으로는 측정 후 결정 · 측정 후 결정 · 가정 기각이다.**

채점자 표류 검사에서 판J 채점과 다른 행은 지식 0/36 · 코드 0/15이었다(지식 안 넘음 · 코드 안 넘음).

세 가지를 함께 읽어야 한다.

- **Codex는 재지 못했다.** 이 컴퓨터에서 Codex가 하네스 폴더의 한글 본문을 읽는 길이 서지 않아 응시 전에 뺐다(§2.3).
  D-160 문언의 「가정 확인」은 세 모델이 모두 「메운다」여야 하므로 **이 판에서는 나올 수 없다** — 남는 것은 「가정 기각」
  또는 「측정 후 결정」이다(§5.3).
- **팩 사용이 낮았다.** 켠 조건에서도 지식 답의 다수는 팩을 거의 보지 않았다 — 도구를 한 번도 부르지 않은 답 Opus 11/60 ·
  Sonnet 24/60, Read로 파일을 연 답 6/60 · 5/60(나머지 답은 Grep이 돌려준 맞는 줄만 봤다), 「팩을 확인하지 않았다」고 답에
  스스로 적은 답 4/60 · 8/60(§3.6). 이 결과는 「팩이 있으면 메운다」가 아니라 **「팩을 열어 두고 한 줄 길잡이만 줬을 때
  모델이 실제로 한 것」**이다(§5.1).
- **처방은 바꾸지 않았다.** 판J의 「유지」 처방은 그대로이고, 이 판의 판정이 그 근거 문장에 미치는 영향만 §4.3에 적는다.

## 1. 질문 · 전제

### 1.1 질문 — 판J가 재지 않은 가정

판J 문서 §0은 스스로 이렇게 적었다.

> 「지금 하네스가 그 빈틈을 실제로 메운다」는 켠 채와 끈 채를 견주는 실제 비교(§6 ①) 전까지 확인되지 않은 가정이다. 아래 「유지」 처방은 미리 정한 규칙(맨 모델이 모자라면 유지)을 따른 것이고, 그 규칙도 이 가정 위에 서 있다.

판J 문서 §6 ①(실제 비교 1회)의 이유 칸은 「이 판은 하네스를 켠 조건도, MCP를 붙인 조건도 재지 않았다 — 「하네스가 빈틈을 실제로 메우는가」 · …」였다.
소유자는 그 비교의 **SAP 없는 반쪽**을 다음 판으로 정했다(D-159 ⓒ). 이 판이 그 반쪽이다 — 같은 문항을 켠 조건으로 다시
풀게 하고, 판J의 맨 모델 결과와 견준다.

### 1.2 「메운다」를 무엇으로 읽나 — 사전 등록된 선 (D-160 원문 그대로)

선은 응시 전에 D-160에 적었고, 결과를 본 뒤 옮기지 않았다. 아래 문장은 D-160에서 글자 그대로 옮겼다(자가 대조 K-84 [2]가
원문과 대조한다). 「메운다」는 「켠 조건의 모델이 판J(D-156)의 『이미 안다 · 이미 잘 짠다』 선에 닿는다」로 읽는다 — 선은
판J와 같고 바뀌는 것은 지식의 분모 하나다.

- **지식 분모** — 주 분모 = 판정 가능 47(표본 60에서 팩 오류 5 · 판정 불가 8을 뺀 것). 엄격 60은 병기만 한다.
- **지식 선** — 지식 선(모델마다 · 전체 47과 범주별 판정 가능 분모 둘 다): 정답률 띠 — ≥ 95% 「메운다」 · 90~95% 측정 후 결정 · < 90% 「못 메운다」 / 비싼 항목 띠 — 오답 0 통과 · 1 측정 후 결정 · ≥ 2 「못 메운다」 / 판정 = 두 띠 가운데 나쁜 쪽.
- **코드 선** — 코드 선(모델마다 · D-156 ⑵ 그대로): 5/5 「메운다」 · 4/5 측정 후 결정 · ≤ 3/5 「못 메운다」.
- **해친다** — 해친다 — 어떤 모델이든 켠 조건이 판J보다 지식은 판정 가능 분모(전체 47 또는 범주)에서 2문항 이상 · 코드는 통과 1과제 이상 적으면 그 칸은 띠와 무관하게 「해친다」로 적는다(지식 1문항 차는 1회 응시의 흔들림으로 본다).
- **L1-f 결합** — 같은 층을 두 시험이 잴 때 코드 시험이 주이고 지식 시험은 거부권만 갖는다. 모델마다: 코드 「메운다」(5/5) ∧ 지식 K-ABAP 판정 가능 6문항 6/6 → 「메운다」 · 코드 5/5 ∧ 지식 < 6/6 → 측정 후 결정 · 코드 4/5 → 측정 후 결정 · 코드 ≤ 3/5 → 「못 메운다」(지식 결과와 무관). 이 규칙은 판K 결과에만 쓴다(판J의 L1-f 칸에 소급하지 않는다).
- **층 판정** — 층 판정 — L1-a(모듈) · L2(페르소나 — 모듈 칸이 대신 잰다) · L1-f(위 결합 규칙)를 세 모델 모두로 읽는다: 셋 다 「메운다」 → 가정 확인(유지 처방의 전제가 선다) · 하나라도 「못 메운다」 또는 「해친다」 → 가정 기각(그 모델에서는 하네스를 켜도 모자란다 — 유지 처방은 그대로 두되 근거 문장을 고치고, 팩 품질 · 적재 길을 다음 판 후보로) · 그 밖 → 측정 후 결정.
- **3사 중립** — Claude 둘은 「메운다」인데 Codex만 아니면 그 사실을 따로 적는다(판J 문서 §2.3).

판J 기준선(판정 가능 분모 · J-83 §2 · §3 · §5)은 D-160에 적힌 값이다 — 전체 Opus 42/47 · Sonnet 43/47 · Codex 44/47, 모듈
13/18 · 14/18 · 15/18, ABAP 일반 작법 · 나라 · 업종은 셋 다 만점, 코드는 셋 다 2/5(C-03 · C-05). 이 문서 §3의 「판J」 열은
이 값을 집계(K-83)가 다시 읽어 옮긴 것이다. ⚠ 모듈 18문항에서 95%는 18/18뿐이다(17/18 = 94.4%).

### 1.3 모델 집합 — 셋이 아니라 둘

D-160은 판J와 같은 세 모델(`claude-opus-5-5` · `claude-sonnet-5-5` · `gpt-5.6-sol`)을 응시자로 정했다. Codex(`gpt-5.6-sol`)는
응시 전 카나리아에서 폴더를 읽는 길이 서지 않아 소유자 결정으로 뺐다(§2.3). 그래서 응시는 **Claude 두 모델**이고, 지식은
60 × 2 = 120행 · 코드는 5 × 2 = 10행이다. 판J의 Codex 기준선은 §3의 표에 옮겨 두되 켠 조건 칸은 「측정 불가」로 적는다.

### 1.4 무엇을 재지 않는가

D-160 정직 유보 ⑷를 그대로 잇는다 — 절차(L3)가 실제 세션에서 지식을 싣는 효과 · 정책(L4) · MCP를 붙인 실력 · 활성화 성공 ·
실제 사람 시간(전부 판J 문서 §6 ①의 SAP 있는 반쪽 — 별판) · 검사기의 값(L6 — 켠 조건에서도 모델은 검사기를 못 돌린다) ·
토큰 비용의 판정(사용량은 병기만) · 사고 재현 문항(K-INC 47 · C-INC 9) · L1-c · L1-e. 여기에 이 판에서 하나가 더해졌다 —
**Codex의 켠 조건**(§2.3).

## 2. 방법

### 2.1 켠 조건 — 판J 격리 레시피에서 바꾼 것 하나

판J 격리 레시피(J-02)에서 바꾼 것은 「하네스 폴더를 읽을 수 있음」 하나이고, 떼어 낼 수 없는 세 손질로 구현했다(D-160 ⓪).
판J와의 차이 전수표는 [K-01](2026-11-08-harness-on-comparison-data/K-01-diff-from-panJ.txt), 명령 글자 그대로는
[K-00](2026-11-08-harness-on-comparison-data/K-00-recipe.txt)이 정본이다.

- **폴더** — 커밋 `4f12d678`의 `interactive/core/knowledge/` · `interactive/core/personas/`를 레포 밖 임시 폴더(git 저장소
  아님)에 풀었다 — 203파일 · 약 1.13 MB. 지식 시험용 · 코드 시험용으로 **같은 내용의 사본 두 벌**을 따로 두었다(K-00 §0).
  모델마다 응시 시작과 끝에 203파일의 blob을 다시 재어 대조했고, 네 번 모두 같았다(K-50-folder-integrity ·
  K-60-folder-integrity · K-00 §6).
- **도구** — Claude: `--tools "Read,Grep,Glob" --restricted`. `--restricted`(명령 실행 도구를 빼고 파일 도구를 작업 폴더
  안에 가둔다)는 D-160 ⓪의 「나머지 플래그는 글자 그대로」에 대한 **첫 번째 예외**다(K-00 §2 · K-01).
- **고정 줄** — 판J의 「기억에서 · 도구 · 파일 금지」 줄을 아래 두 줄로 바꿨다(첫 줄 지식 · 둘째 줄 코드 · 영문이 정본).
  한국어 뜻 옮김은 판J처럼 괄호로 붙였다(K-00 §1 · 사양 §3.6 ⓒ).

  ````text

You may read the files in the current folder (SAP knowledge pack: knowledge/ - consultant personas: personas/, start from personas/INDEX.md if unsure where to look). Do not use web search, do not read anything outside the current folder, and do not create or modify any file.
  Write the complete ABAP source as a single file and return it in one ```abap code block, with no explanation outside the block. You may read the files in the current folder first (SAP knowledge pack: knowledge/ - ABAP conventions: knowledge/abap/conventions/).   ````

- **유효성 — 「시도」 기준**(사양 §3.6 ⓓ) — 답안마다 이벤트 기록에서 기계로 센다: 도구 호출이 읽기 계열뿐 · 읽은 경로가 전부
  폴더 안 · 웹 · MCP · 파일 쓰기 0 · 답의 URL은 팩 본문에 있는 문자열만. 폴더 밖을 **읽으려 한 시도**는 실제로 읽혔는지와
  무관하게 위반이다(K-00 §4). 위반이 하나라도 있으면 그 시도는 무효다. 세 번 무효면 그 행은 오답(빼지 않는다 — 「메운다」 쪽으로 기울지 않게). 되묻기 · 답 없음도 오답이다.
- **실패 분류**(사양 §3.6 ⓔ) — ① 전이 오류(사용량 한도 · 네트워크 등)는 고정 백오프 뒤 같은 문항을 다시 부르고 시도 수에
  넣지 않는다 ② 무효 시도는 시도 수에 넣고 최대 3회 ③ 성공으로 끝났는데 답이 없으면 오답. 호출 하나의 벽시계는 900 s다
  (K-00 §5). 실제로는 지식 120행 · 코드 10행 모두 첫 시도에 유효했다 — 무효 0 · 전이 재시도 0 · 답 없음 0(§3.6 ·
  K-60-retries).
- **세션 고정** — 한 문항 = 한 CLI 호출 = 새 세션(판J와 같다).

### 2.4 채점

판J의 흐름(판J 문서 §2.5)을 그대로 따랐다.

- **블라인드 묶음**(K-65) — 지식 156행(켠 조건 120 + 표류 검사 36) · 코드 25행(켠 조건 10 + 표류 검사 15). 행마다 익명 id를
  붙이고 시드로 섞고(판K 시드 20261108 · 용도별 스트림 — K-00 §8) 조건 · 모델 표시를 뗐다. 답 본문은 고치지 않았다. 익명 id ↔
  조건 · 모델 대응표(매핑)는 레포 밖에만 두고 채점자에게 주지 않았다.
- **채점자** — A · B · 제3 판정 = Claude Fable 5.1(`claude-fable-5-1`)의 서로 다른 새 컨텍스트. 메모 첫 줄에 관측 모델 id를
  적었다(K-70 · K-71 · K-80). 둘이 갈린 행만 제3 판정이 1차 자료(답 원문 · 정답 키 · `grading_rule` · 인용 파일 줄)로 다시
  판정했다 — 지식 2행 · 코드 10행(K-80 ①).
- **접근 기록 검사**(K-72) — 채점자가 허용 목록 밖(매핑 · 다른 채점자 파일 · 판J 채점 결과 등)에 닿았는지를 원 기록에서
  기계로 셌다. 회차마다 한 절이다. 1회차 A · B 접촉 0 · 관측 id 일치 · PASS. 2회차(제3 판정자) — 도구 호출 34 · 허용 34 · 접촉 0 ·
  관측 모델 id `claude-fable-5-1` 전부 일치 · 메모 머리 일치 · PASS. 3회차(독립 리뷰 R-F)는 회수가 K-72 3회차 절과 함께 적는다 —
  이 문서는 회수 커밋에서 갱신된다.
- **판J 규약 승계** — 판정 어휘(지식 정답 / 오답 / 팩어긋남의심 · 코드 위반 / 통과) · `grading_rule` · `general_rules` ·
  오류급 정의 · 같은 검사기 번들. 채점 지시문은 「답에 파일 경로나 인용이 들어 있어도 그것은 판정의 근거가 아니다」라고
  적었다(K-65-grader-brief).
- **정답 키 동결** — 판J 최종 키(J-10 + J-81 팩 감사 판정)를 그대로 쓴다. 판K는 팩 감사를 다시 하지 않는다. 켠 조건의 답이 키와 어긋나 키가 의심되는 새 행은 「새 의심」 목록에 적기만 한다.
- **비교 불가** — 관측 모델 id(Claude 이벤트 필드 · Codex 배너)가 판J와 다르면 그 모델의 칸은 「비교 불가」로 적고 판정하지 않는다. 관측 id 대조는 §3.5.

### 2.5 표류 검사와 비교 기준

판J 맨 모델 답안 일부(지식 36행 · 코드 15행 전부)를 켠 조건 답안 사이에 표시 없이 섞어 같은 채점자가 다시 채점했다.
문턱은 D-160 그대로다 — 판J 최종 판정과 다른 행이 지식 5행 이상(일치 ≤ 31/36 = 86.1%) 이면 지식 비교 칸 전부, 코드의 과제 통과 판정이 2행 이상 다르면 코드 비교 칸 전부를 「측정 후 결정」으로 둔다.

**비교 기준 — 「판J 최종 판정」을 무엇으로 읽나**(사양 §7 ⓤ · 사용자 결정 2026-11-08). 문언의 「판J 최종 판정」을 J-83의
`final` 칸으로 읽으면, 팩 오류 5문항에서 그 칸은 팩 감사(J-81) 뒤 **공식 문서 쪽 키로 다시 잰 값**이다. 판K 채점자는 동결된
팩 키로 채점하므로 그 행들에서는 채점자가 같아도 **반드시** 어긋난다 — 그것은 채점자 표류가 아니다. 그래서 판J 쪽 기준을
**판J 채점 단계의 최종**(A · B → 제3 판정까지 · 팩 감사 전)으로 읽었다. 문언대로 J-83 `final`과 견준 수도 §3.4에 함께
적는다. 이 읽기는 표류 집계를 본 뒤에 정해졌다(§5.4).

### 2.6 결합

- **팩어긋남의심 = 오답**(사양 §7 ⓛ) — 켠 조건 행을 채점자가 「팩어긋남의심」으로 적으면 집계는 오답으로 센다. 키를 동결했으므로
  키와 다른 답을 맞다고 셀 수 없다. 켠 조건에 불리한 방향이다(§5.5).
- **코드 과제 통과 = 검사기 ∧ 채점** — 동봉 검사기 오류급 0(기계 · K-60-checker-summary) **그리고** 일반 작법 위반 0(채점자 A ·
  B → 제3 판정). 검사기 결과를 채점자가 뒤집지 않고, 채점자의 위반 판정을 검사기 결과로 지우지 않는다.
- **판정 칸 옮기기** — 집계 스크립트(K-83)가 선을 문언대로 적용하고, 이 문서의 판정 · 수치 칸은 그 집계에서 기계로만
  옮긴다(K-84 `--fill`). 이 문서를 쓴 손은 칸을 쓰지 않는다(§2.7).

### 4.3 「유지」 처방의 근거 문장에 미치는 영향

판J의 「유지」 처방은 두 문장에 기대고 있다. 하나는 판J 문서 §0의 「아래 「유지」 처방은 미리 정한 규칙(맨 모델이 모자라면
유지)을 따른 것이고, 그 규칙도 이 가정 위에 서 있다」이고, 다른 하나는 판J 문서 §4.3 L1-a 행의 「두 모델 규칙: Opus ✗ → 유지.」다.
D-160은 판정마다 이 문장들을 어떻게 다룰지 미리 정했다 — 가정 확인이면 「유지 처방의 전제가 선다」, 가정 기각이면 「유지 처방은
그대로 두되 근거 문장을 고치고, 팩 품질 · 적재 길을 다음 판 후보로」, 그 밖이면 측정 후 결정이다(§1.2).

이 판의 칸은 그 세 갈래로 이렇게 갈린다(§4.1 · K-83 §9). L1-a · L2는 **측정 후 결정**이다
— Opus 모듈 17/18 = 94.4%(측정 후 결정) ·
Sonnet 모듈 18/18(메운다) · Codex 측정 불가. L1-f는 **가정 기각**이다 — 코드
Opus 3/5 · Sonnet 2/5(판J Opus 2/5 · Sonnet 2/5 · 해친다 Opus 아니오 · Sonnet 아니오).
그러므로 「유지」 처방 문장의 근거는 **세워지지도 흔들리지도 않았다** — 지식 층(L1-a · L2)은 측정 후 결정이고, 작법 층(L1-f)은
켠 조건으로도 메워지지 않음이 드러났다. D-160이 가정 기각에 붙인 처리(유지 처방은 그대로 두되 근거 문장을 고치고, 팩 품질 ·
적재 길을 다음 판 후보로)는 L1-f에 걸린다. 이 문서는 처방도 판J 문서도 고치지 않는다 — 근거 문장을 고치는 일은 마감 결정과
다음 판의 몫이다.

## 5. 정직 유보

### 5.1 ⑴ 팩 사용이 낮았다

§3.6대로 켠 조건의 지식 답 다수는 팩을 Read로 열지 않았고, Opus 11/60 · Sonnet 24/60은 도구를 한 번도 부르지 않았다. 「팩을
확인하지 않았다」고 답에 스스로 적은 답도 4/60 · 8/60이다. 이것은 두 방향으로 읽기를 막는다. 지식 칸이 판J보다 올라간
것(§3.1)은 팩을 읽어서라고 단정할 수 없다 — 팩을 보지 않은 답이 적지 않으므로, 그 차이의 일부는 모델 쪽 변화나 1회 응시의
흔들림일 수 있다(D-160 정직 유보 ⑵ — 대조군이 없다). 코드 칸이 「못 메운다」인 것은 「팩이 있어도 모자란다」가 아니라 「규약 폴더를
열어 두고 한 줄 길잡이만 주면 모델이 규칙의 출처를 찾아 읽지 않는다」일 수 있다 — 채점 규칙의 출처 두 파일은 10답 중 1답만
열었다. 둘을 이 판은 가르지 못한다. 제품의 실제 적재 길(절차가 1-hop으로 파일을 싣는 것 · L3)은 이 판이 재지 않았다(§1.4).

### 5.2 ⑵ 가림은 부분적이었다

채점자는 조건 · 모델 표시 없이 받았지만, 켠 조건 지식 답의 79/120이 팩 경로를 인용했고 섞어 넣은 판J 답은 0/36이다(K-65-check
[6]) — 경로 인용만으로 조건을 짐작할 수 있었다(D-160 정직 유보 ⑺이 예상한 대로). 답 본문은 고치지 않았다. 방어는 둘이다 —
채점 지시문이 「답에 파일 경로나 인용이 들어 있어도 그것은 판정의 근거가 아니다」라고 적었고, 표류 검사(§3.4)가 같은 채점자의
판J 답 채점이 판J와 얼마나 다른지를 잰다. 그러나 「켠 조건 답에만 다르게 채점했는가」는 직접 재지 못한다.

### 5.3 ⑶ Codex 측정 불가 — 세 모델 문언으로는 「가정 확인」이 불가능하다

D-160의 층 판정은 「세 모델 모두로 읽는다」이고 「셋 다 메운다 → 가정 확인」이다. Codex 칸이 측정 불가이므로 이 판의 결과가
무엇이든 세 모델 문언은 「가정 확인」에 닿지 않는다 — 「가정 기각」(Claude 하나라도 못 메운다 · 해친다) 또는 「측정 후 결정」뿐이다.
「Claude 둘」 열은 문언이 아니라 병기다. Codex를 다시 재려면 셸 출력의 한글 깨짐(§2.3 2회차 ⓑ)을 먼저 풀어야 하고, 그것은 설치나
명령 분류 규칙으로 고쳐지지 않았다(K-00 §10). Codex 재채점 · 교차 리뷰도 보류다(2026-11-12 이후).

### 5.4 ⑷ 표류의 비교 기준을 결과를 본 뒤 바꿨다

표류 문턱의 문언은 「판J 최종 판정과 다른 행」이다. 이 판은 그 「판J 최종」을 J-83 `final`이 아니라 판J 채점 단계의 최종으로
읽었다(§2.5 · 사양 §7 ⓤ · 사용자 결정 2026-11-08). 이유는 팩 오류 문항에서 J-83 `final`이 공식 문서 쪽 키라 동결 키로 채점하는
판K와 반드시 어긋난다는 데 있지만, **이 읽기는 표류 집계를 본 뒤에 정해졌다.** 사전 등록의 정신에서 벗어난 자리이므로 문언 기준
수치를 §3.4에 함께 적었다 — 독자는 두 기준의 결과를 나란히 볼 수 있다.

### 5.5 ⑸ 팩어긋남의심 = 오답은 켠 조건에 불리하다

켠 조건 답을 채점자가 「팩어긋남의심」으로 적으면 집계는 오답으로 센다(§2.6 · 사양 §7 ⓛ). 그 답이 실제 SAP에 맞을 수도 있다는
뜻이므로, 이 규칙은 켠 조건의 정답률을 낮추는 쪽으로만 작용한다. 맨 모델(판J)에서도 같은 규칙이었는지는 판J 집계의 정의를
따른다 — 판J는 팩 감사로 그 행들을 다시 판정했고(J-81), 판K는 팩 감사를 하지 않는다. 새 의심 행은 §3.2에 적었다.

### 5.6 ⑹ 팩 의심 목록 — 감사하지 않았다

채점자 A · B의 메모와 제3 판정 메모(K-80 ⑤)가 팩 쪽이 의심스럽다고 적은 문항이 있다 — QM-01 · WM-01 · BW-01 · FI-02 · MM-01 ·
PP-01 · ABAP-01 · TM-01 · HCM-01(항목 전제). 이 판은 팩 감사를 하지 않는다(정답 키 동결) — **목록만 옮기고 판정에 쓰지 않았다.**
제3 판정이 유보하거나 보류한 문항(CO-02 · WM-02 · TM-02)도 K-80 ⑤에 있다. 팩 품질은 D-160이 「가정 기각」일 때의 다음 판 후보로
적어 둔 자리다.

### 5.7 ⑺ 작성자 = 응시 모델

러너 손질 · 묶음 · 집계 · 이 문서 · 자가 대조를 쓴 작업자가 응시 모델(Opus 5.5)이다(§2.7 · D-160 정직 유보 ⑼). 방어는 판정 ·
수치 칸을 손으로 쓰지 않는 것 하나다 — 1부 초안은 그 칸을 자리표시로만 썼고, K-84 `--fill`이 K-83에서 옮겼으며, K-84 [3]이 같은
JSON에서 다시 풀어 대조한다. 그러나 **어느 칸을 표에 둘지 · 문장을 어떻게 쓸지**는 이 작업자가 정했다. 그 몫은 시험을 보지 않은
Fable의 독립 리뷰(§6)가 본다.

### 5.8 ⑻ 채점자 규약 충돌 자리

채점자 A · B는 같은 지시문을 다르게 읽은 자리가 있었다 — 지식의 「주답 + 보충」과 헤지의 경계 · 팩어긋남의심의 요건, 코드의
C-01 규칙6(빈 CATCH의 범위) · C-02 규칙7(given-when-then 이름) · C-04 규칙5(SELECT 결과 검사의 등가) · C-04 규칙2(위반 대표 줄),
그리고 규칙 집합은 같고 표기만 다른 행(K-80 ②). 제3 판정이 1차 자료(J-10 · J-11 원문 · 인용 파일 줄)로 각 자리의 원칙을 한 줄씩
정해 닫았다. 다른 읽기를 택했으면 몇몇 코드 과제의 통과가 바뀌었을 수 있다 — 특히 C-04 규칙5는 제3 판정 스스로 「목적 독해면
반대」라고 유보를 적었다.

### 5.10 ⑽ K-99 이름 검사의 SID 꼴 예외

마감 게이트의 이름 검사(K-99)는 대문자 3자 낱말을 SID 꼴로 잡는다. 답안은 고치지 않으므로, 모델이 지어낸 3자 낱말(예: 코드 답의
ALV 열 이름)이 걸리면 sap.env 값 · 이름 목록과 겹치지 않음을 확인한 뒤 예외 목록에 더했다. 그 목록이 판 도중 세 번 늘었다 — 낱말 13 + 구조 예외 1.

| 회차 | 더한 것 | 이유 | 커밋 |
|---|---|---|---|
| 1 | 낱말 `CNT` | 코드 답이 지어낸 ALV 열 이름 | `a8477e12` |
| 2 | 낱말 `MOD` `CTY` `IND` `ERR` `L47` `LPF` `NIC` `OOS` | 문항 id 토큰 · 답안 약어 | `cce51bfc` |
| 3 | 구조 예외 — 판J 자료 폴더 본문에 있는 3자 토큰은 허용 | 걸린 낱말 `FAE` `OFF` `EPI` `TNT` | `0ffc0cbf` |

답안은 한 글자도 고치지 않았다. 예외 낱말이라도 sap.env 값 · 이름 목록과 겹치면 여전히 위반이다. 그래도 예외 목록이 커질수록
진짜 식별자를 놓칠 자리가 는다 — 특히 구조 예외는 낱말 하나하나가 아니라 판J 자료 폴더 전체를 허용 근거로 삼는다.

### 5.12 ⑿ 응시 CLI의 전역 설정 — 기록되지 않은 변수

응시 이벤트의 `init` 줄을 보면 지식 120호출 · 코드 10호출 모두 `plugins=4`(cc-plugin-agents-md · cc-plugin-telemetry ·
cc-plugin-privacy · cc-plugin-plugin-authoring) · `agents=6` · `skills=0`이다(K-50-events · K-60-events). 카나리아 ①의 자기 보고는
「plugins: none」이었다 — 모델이 자기에게 실린 플러그인을 보지 못한다는 뜻이고, 카나리아 ①의 통과 기준은 `init`의 도구 목록(정확히
Read · Grep · Glob)이라 판정은 그대로다. 하네스 폴더에는 AGENTS.md · CLAUDE.md · `.claude`가 0이다(K-00 §0 폴더 검증). 그러나
**응시 컴퓨터 사용자의 전역 CLAUDE.md가 응시 컨텍스트에 들어갔는지는 K-00에 기록되지 않았다** — `--setting-sources ""`와
`--restricted`가 설정 파일을 막지만, cc-plugin-agents-md가 무엇을 싣는지는 재지 않았다. 판J의 이벤트(J-50)에도 같은 `plugins=4` ·
`agents=6`이 있다 — 같은 종류의 조건이지만 다른 컴퓨터라 실린 내용은 다를 수 있다. 그래서 이것을 켠 · 맨 비교의 **공통 배경**으로
두되 **기록되지 않은 변수**로 적는다.
