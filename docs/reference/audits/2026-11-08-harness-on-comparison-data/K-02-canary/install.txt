[3] PowerShell 7.6.9 — msi(x64 · 전 사용자용) 설치 + [2] 의 msix 꾸러미 제거
    왜: [2] 의 msix pwsh 는 Codex 샌드박스(windows.sandbox="unelevated")의 제한 토큰으로 띄우지 못한다(CreateProcessAsUserW 5 ·
        Codex 실행 파일 안의 진단 문구도 「packaged (MSIX) app … cannot be launched inside a sandboxed container. Uninstall the packaged
        version and install an unpackaged build」). 설치 없는 길(Windows PowerShell 5.1)을 먼저 쟀다 — K-00-recipe.txt §10 해결 경위.
    내려받기: PowerShell 저장소 GitHub 릴리스 v7.6.9 의 PowerShell-7.6.9-win-x64.msi (117493760 바이트 · 주소는 이 폴더 URL 규칙상 적지 않는다)
              같은 릴리스의 hashes.sha256 를 먼저 받아 대조 — 설치 전에 맞춤:
              기대(hashes.sha256 의 *PowerShell-7.6.9-win-x64.msi 행) = 50d33c7494aaf82b987cfd4de3f232d04f91fdd4c0deeca8a669cced3e7cf8f9
              실측 Get-FileHash SHA256                                  = 50d33c7494aaf82b987cfd4de3f232d04f91fdd4c0deeca8a669cced3e7cf8f9 → 같음
              Authenticode 서명 = Valid (Microsoft Corporation)
    설치: Start-Process msiexec -ArgumentList '/i','<msi>','/quiet','ADD_PATH=1' -Verb RunAs -Wait — UAC 창이 떴고 사용자가 승인했다
          (대기 포함 29 s) · msiexec exit=0
    확인: C:\Program Files\PowerShell\7\pwsh.exe --version = PowerShell 7.6.9 · 컴퓨터 PATH 에 C:\Program Files\PowerShell\7\ 추가됨
    msix 제거: Remove-AppxPackage Microsoft.PowerShell_7.6.9.0_x64__8wekyb3d8bbwe (현재 사용자 · UAC 없음) → Get-AppxPackage 0개 ·
          %LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe 별칭 사라짐.
          제거 이유(과업 조건 「Codex 가 여전히 msix 쪽을 고르면」 충족 · 진단 호출 실측): pwsh 7 은 켜질 때 자기 자리($PSHOME)를 PATH 앞에
          붙이므로, 러너를 msix pwsh 로 띄우면 Codex 도 msix pwsh 를 골라 셸이 전부 실패한다(msi 를 깐 뒤에도 같음). msi pwsh 로 띄우면 Codex 는
          msi pwsh 를 고른다. 설치 전에 켜진 세션의 PATH 에서는 「pwsh」가 msix 별칭으로 풀리므로, 꾸러미를 지워 그 길을 닫았다(fail-closed —
          잘못된 셸로 조용히 도는 대신 pwsh 를 못 찾고 멈춘다).
    정리: 내려받은 msi · hashes.sha256 · 설치 기록(%TEMP%\sapkit-panK\msi\)은 설치 뒤 지웠다([IO.Directory]::Delete).
