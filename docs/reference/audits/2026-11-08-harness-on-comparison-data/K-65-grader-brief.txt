K-65-grader-brief.txt — 블라인드 채점 지시문 (채점자 A · 채점자 B · 제3 판정 공통)
=====================================================================================

0. 역할
-------
  - 당신은 블라인드 채점자다. 두 묶음의 행에는 서로 다른 조건(어떤 환경에서 답을 썼는가)과 서로 다른 모델이 쓴 답이
    섞여 있고, 행 순서도 섞여 있다. 어느 행이 어느 조건 · 모델의 것인지 **추정하지 말라** — 추정을 적지도, 추정에 따라
    판정을 바꾸지도 않는다. 답에 파일 경로나 인용이 들어 있어도 그것은 판정의 근거가 아니다 — 답의 내용만 본다.
  - 행마다 **독립으로** 판정한다. 같은 문항 · 과제의 다른 행과 견주어 판정을 맞추지 않는다 — 규칙(grading_rule ·
    general_rules)과 키(answer_key)에만 맞춘다.
  - 정답 키와 규칙은 고치지 않는다. 키가 실제 SAP 와 어긋난다고 보면 그 행을 팩어긋남의심으로 적고 근거를 남긴다.

2. 금독 — 허용 목록 밖 전부 (열지 않는다 · 목록도 보지 않는다)
-----------------------------------------------------------------
  - 위 두 자료 폴더에서 허용 목록에 적은 파일 말고는 어떤 파일도 열지 않고, 그 폴더나 하위 폴더의 목록을 보지 않는다
    (답안 · 코드 · 검사기 출력 · 실행 기록 · 요약 표 · 이전 채점 · 판정 · 집계 · 자체 검사 파일 전부가 여기 든다).
  - 이 묶음을 만든 스크립트와 그 검사 결과(K-65-build-blind.mjs · K-65-check.txt)도 금독이다.
  - 채점자 A · B 는 다른 채점자의 출력(K-70 · K-71 · K-80 으로 시작하는 파일)을 열지 않는다 — 자기 것만 쓴다.
  - 레포 안의 점(.)으로 시작하는 폴더 전부 · 레포 밖 전부(임시 폴더 · 홈 폴더 포함)는 금독이다.
  - 파일 찾기 · 내용 검색(Glob · Grep 류)은 허용 목록의 경로를 지정해서만 쓴다 — 경로 없이 레포 전체를 뒤지지 않는다.
  - 접근 기록 검사: 도구 호출의 경로를 기계로 잰다. 허용 목록 밖 접촉이 1건이라도 있으면 그 채점은 무효다.

3. 묶음 형식
------------
  K-65-blind-knowledge.json  { meta, rows[156] } — 행 칸: anon_id · kind="knowledge" · item_id · question · grading_rule ·
                             answer_key · answer.  question · grading_rule · answer_key 는 J-10 글자 그대로, answer 는 답 원문
                             무편집(답이 없거나 「모른다」면 그 글자 그대로).
  K-65-blind-code.json       { meta, rows[25] } — 행 칸: anon_id · kind="code" · task_id · task_text · required_output ·
                             general_rules · checker_error_grade · code.  general_rules 는 J-11 그 과제의 번호 규칙 절이다.
  checker_error_grade        동봉 검사기의 기계 결과(오류급 수 · J-11 §0 정의). **뒤집지 않는다** — 채점자는 일반 작법
                             (general_rules 번호 규칙)만 본다. 과제 통과 = 오류급 0 ∧ 일반 작법 위반 0 (J-11 §0) 이지만,
                             이 채점의 verdict 는 일반 작법만으로 정한다(합치는 것은 집계가 한다).
  코드 줄 번호                code 칸 본문을 줄바꿈(\n)으로 나눈 물리 줄 · 1부터.
  meta                       시드 · 스트림 · 행 수 · 입력 지문 — 채점에는 쓰지 않는다.

4. 판정 어휘 (J-70 §1 · 선행 채점이 쓴 어휘 그대로)
---------------------------------------------------
  지식  verdict = 정답 | 오답 | 팩어긋남의심
        detail  = 완전 (정답일 때)
                | 부분 · 다른값 · 무응답 (오답일 때 — 요구 요소 일부만 / 키와 다른 식별자 · 주장 / 답을 내지 않음 · 모른다)
                | 의심:<짧은 근거> (팩어긋남의심일 때)
  코드  verdict = 위반 | 통과
        detail  = 위반한 general_rules 번호와 줄을 「번호@줄」로, 여럿이면 세미콜론으로 잇는다(예: 5@56;6@114).
                  통과면 빈 칸. 줄은 위반이 드러나는 대표 줄 하나(AUTHORITY-CHECK 부재는 그 SELECT 줄).
                  검사기 오류급은 detail 에 넣지 않는다.

5. 선행 채점 규약 발췌 — 채점자 A 는 §5-A, 채점자 B 는 §5-B 를 따른다
----------------------------------------------------------------------
  같은 채점자를 규약으로도 맞추기 위해, 앞선 채점에서 각 채점자가 적은 규약 절을 발췌했다(문항 · 행별 판정 예시 · 모델
  이름 · 수 · 이 묶음에 없는 갈래(사고 · 재현 코드)는 뺐다 · 뺀 자리의 원칙 문장은 남겼다). 제3 판정은 둘을 모두 읽고,
  A · B 가 갈린 행에서 J-10 · J-11 원문(괄호의 판정 기준 포함)을 기준으로 정한다.

  §5-A  (채점자 A 규약 — J-70 §1 발췌)
    [지식]
    - 정답 = grading_rule의 '+'로 묶인 요구 요소를 전부 담았을 때. 하나라도 빠지면 오답(detail=부분).
    - 단일 답에 "~로 기억한다/~일 것이다" 식의 보류 표현이 붙은 것은 정답으로 본다(답은 하나다).
    - 둘 이상을 나란히 "X 또는 Y"로 내면 오답. (규칙이 복수 후보를 허용한 항목만 예외.)
    - 다른 해석을 위한 각주식 부기("만약 ~를 묻는 것이면 ~")는 보류로 보지 않는다 — 본답이 하나로 서 있으면 본답만 본다.
    - 규칙 밖의 덧말이 틀려도 판정을 바꾸지 않는다. 단, 요구 사실과 모순되는 덧말이면 오답.
    - detail: 요구 요소 일부만 있으면 부분 · 키와 다른 식별자/주장이면 다른값 · 답을 내지 않거나 모른다고 하면 무응답.
    - 답변 언어(한/영)는 무관.
    - 팩어긋남의심은 "키보다 답이 실제 SAP에 맞을 가능성이 있다"고 내가 보는 경우에만 쓴다. 키는 손대지 않는다.
    [코드 C-01~C-05]
    - 11-code-tasks.txt의 번호 규칙만 센다. 01-convention-split.txt의 집 규칙(접두사·include 구조·텍스트 요소·OK_CODE·
      두 클래스 분리·템플릿·ALV 기본값)은 세지 않고 메모에 적는다.
    - 번호 규칙 목록에 없는 일반 작법(예: C-01의 주석 배너)도 세지 않는다 — 계약이 "번호 규칙"이라서다.
    - SELECT ... INTO TABLE 직후 대상 테이블 IS INITIAL 검사는 sy-subrc 검사와 동등으로 인정한다.
    - 판단이 갈릴 수 있는 적용: ⓐ C-01 규칙6 — CATCH cx_salv_not_found를 빈 블록(주석만)·RETURN만으로 끝낸 것을 「오류를
      삼킴」으로 센다. ⓑ C-02 규칙4 — 예외 클래스를 FINAL로 두지 않은 것을 센다(상속 설계 근거 없음). ⓒ C-02 규칙5 —
      public 시그니처에 쓰인 public TYPES는 세지 않는다. ⓓ C-02 규칙7(given-when-then 이름)은 무의미한 이름만 세는
      쪽으로 느슨하게 적용한다.
    - 규칙@줄번호의 줄번호는 위반이 드러나는 대표 줄 하나(AUTHORITY-CHECK 부재는 그 SELECT 줄).

  §5-B  (채점자 B 규약 — J-71 §1 지식 · §2 코드 발췌)
    [지식]
    - 정답 = grading_rule이 요구하는 사실이 답에 진술돼 있을 때만. 상세는 「완전」.
    - 「기억으로는 ~ / 시스템에서 확인 요망」류 단서가 붙어도 단일 답을 냈으면 진술로 본다.
    - 같은 질문에 대해 두 객체를 둘 다 후보로 내거나 「X 또는 Y」로 답하면 목록 → 오답 (규칙이 대안을 허용할 때만 예외).
      주답 하나를 두고 다른 것을 구버전 · 대안으로 병기하면 그 주답으로 판정한다(주답이 키와 다르면 오답/다른값).
    - 다른 시나리오용 객체를 보충으로 언급한 것은 헤지가 아니다.
    - 「주답」 판정 기준: 질문에 직접 대응하는 문장에서 먼저·단정적으로 낸 식별자.
    - 부분 = 규칙이 요구하는 둘 이상의 사실 중 일부만 → 오답/부분. 무응답·「모른다」 → 오답/무응답. 다른 식별자/반대
      사실 → 오답/다른값.
    - 규칙 밖의 틀린 부연은 계수하지 않는다.
    - 답변 언어(한/영/서)는 무관 — 내용으로 판정.
    - 팩어긋남의심 = 여러 답이 일치해서 키와 다른 값을 냈고 채점자 기억도 그쪽이거나, 질문 전제 자체가 의심될 때만.
      키는 건드리지 않는다.
    - 「진짜 동등한 이름」(같은 객체의 다른 표기)은 정답으로 볼 수 있다 — 그렇게 본 행은 메모에 적어 제3 판정이
      확인하게 한다.
    [코드 C-01~C-05]
    - 11-code-tasks.txt의 번호 붙은 general_rules만 계수. detail = `규칙@줄` 세미콜론 목록(줄 = code 칸의 물리 줄).
      집 규칙은 메모에 「미계수」로만 적는다.
    - `SELECT … INTO TABLE` 뒤 결과 테이블 `IS INITIAL` 검사는 sy-subrc 검사와 등가로 인정.
    - 공개 메서드 시그니처에 쓰이는 공개 TYPES는 「공개 필요가 입증된 것」으로 보아 규칙 5(공개 속성 금지) 통과.
    - 규칙 4 FINAL은 파일 안의 모든 클래스에 적용(전역 예외 클래스도 계수).
    - 테스트 메서드 이름 규칙(given-when-then): `normal_discount`·`full_discount`처럼 결과가 없는 시나리오명은 위반으로 본다.
    - 주석 배너(`*---*` 블록)는 규칙이 목록에 있는 과제에서만 계수(C-02 규칙 9 · C-03 규칙 8). 다른 과제의 배너는 메모에만.
    - C-01 규칙 6은 괄호의 cx_salv_msg 처리로 판정. 빈 `CATCH cx_salv_not_found`는 기록만(미계수).
    - C-03 규칙 7(TABLES)은 TABLES가 없으면 해당 없음. C-04 규칙 4는 join이면 해당 없음.
    - C-05 「7.40+ 구문 금지」: 팩 목록 기준. `lines( )`는 7.02부터 있어 통과. MOVE 등 구식 구문은 규칙에 없어 미계수.
    - C-04 규칙 2(서버측 집계): 전 품목을 읽어 ABAP 루프로 합산하면 (SHKZG 부호 처리 사유를 적었어도) 규칙 문언상 위반.
      SUM/COUNT GROUP BY → 통과.
    - 검사기 오류급은 기계 결과 그대로 — 재실행하지 않는다.

7. 쓰기 · 행동 제약
-------------------
  - 쓰는 자리는 자기 출력 파일 둘뿐이다. 묶음 · 이 지시문 · 레포의 다른 파일은 한 바이트도 바꾸지 않는다.
  - 모델 호출 · 웹 검색 · MCP 도구 0. 셸 명령으로 허용 목록 밖을 읽지 않는다. SAP 에 접속하지 않는다.
  - 출력에 비밀 · 식별 정보(계정 · 컴퓨터 이름 · 절대 경로 · 레포 위치)를 적지 않는다 — 경로는 레포 상대로만.
