  판단이고 「여러 답이 일치」는 요건이 아니다. 단일 답이라도 판정자 지식이 답 쪽에 서면 의심, 지식이 없으면
  오답/다른값(B 의 「확장 적용」 9d1461 · 9ebb80 은 이 원칙으로 정당하다 — 갈리지 않아 K-80 에는 없다).
  키와 같은 답은 정답으로 둔다(항목 전제 의심은 메모에만).
- C-01 규칙6 빈 CATCH cx_salv_not_found: J-11 §3 머리 「규칙 번호 뒤 괄호는 채점자용 판정 기준」 — 규칙6 괄호는
  「cl_salv_table=>factory 의 cx_salv_msg 를 빈 CATCH 로 삼키면 위반 · 메시지 출력이나 전파면 통과」로 측정 대상을
  고정한다. 사전 등록된 기준을 다른 CATCH 로 넓히지 않는다 → cx_salv_msg 가 MESSAGE 처리되면 통과, 빈 CATCH
  cx_salv_not_found 는 기록만(B 쪽). 부차 근거: 그 CATCH 는 열 머리글 보조 FORM 에서 리터럴 필드명으로 호출돼 실제로
  날 수 없는 예외이고, 두 행은 주석으로 「무시」 의도를 밝혔다 — clean-code.md:86 의 「handle what you are able to
  handle」 안쪽으로도 볼 수 있다.
- C-02 규칙7 given-when-then: 원문 「Name tests for given-when-then — is_released_returns_true_when_status_is_
  freigegeben, never test01 or test_ok」 — 이름이 기대 결과(then)를 말해야 한다는 적극 요구이고 「never test01」은
  하한일 뿐이다. 시나리오만 있는 이름(normal_discount · full_discount · zero_discount · percent_above_100 ·
  negative_gross · percentage_too_high)은 위반, 결과가 든 이름(…_returns_zero · …_is_rejected · …_rejected ·
  negative_gross_fail · rejected_input)은 통과(B 쪽). rounding_half_up · rounding_to_cents · rounding_to_two_dec 은
  기대 동작을 담아 경계로 보고 세지 않았다 — 어느 행도 그것만으로 갈리지 않는다. A 의 「무의미한 이름만」 독해는
  A 스스로 「느슨하게」라고 적은 대로 원문의 적극 요구를 떼어낸 것이다.
- C-04 규칙5 IS INITIAL 등가의 범위: 원문 「sy-subrc checked after the SELECT」(clean-code.md:145 — 대안은
  CX_SY_OPEN_SQL_DB catch 만). 두 채점자가 공통으로 인정한 등가는 「SELECT 대상/결과 테이블의 IS INITIAL(출력 전)」
  까지다. 그 대상이 아닌 파생 집계 테이블(6c55d7 의 gt_out)의 비어 있음으로 대신하는 것은 SELECT 결과를 검사한 것이
  아니다 → 위반(A 쪽). 정직 유보: gt_out 비어 있음 ⟺ gt_item 비어 있음이라 목적 독해면 B 처럼 통과가 된다 —
  원문과 공통 규약을 우선했다. C-04 다른 4행은 모두 sy-subrc 또는 대상 테이블을 직접 검사했다.
- C-04 규칙2 대표 줄: 「집계 없이 품목 전 행을 읽는 SELECT 첫 줄」로 정규화한다 — 규칙 문언이 「SUM / COUNT + GROUP BY 를
  SELECT 에서」라 결함이 드러나고 고쳐질 자리가 SELECT 이고, 지시문 §4 예(AUTHORITY-CHECK 부재 = SELECT 줄)와 같은
  앵커다. B 의 LOOP 줄도 틀린 표기가 아니라 표기 선택이다.
- 규칙 집합이 같고 표기만 다른 행(fbed8a · 69dad9)은 K-80 에 넣되 정규화한 detail 을 쓰고 reason 에 「표기 차이만 —
