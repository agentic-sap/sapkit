# 첫 제품 경로 실사용 1회 — `create-program` → IDES (2026-11-10 ~ 11)

> **지위**: 기록이다(판이 아니다). 판 큐의 「실사용 1회」(D-163) 행을 닫는 관측 기록이며,
> 결정을 내리지 않는다. 여기 적힌 「처분 후보」는 다음 판의 착수 근거 후보일 뿐이고
> 새 D-결정 전까지 효력이 없다. **사실과 가설을 나눠 적는다.**

## 1. 무엇을 했나

- **대상 시스템**: IDES(프로파일 `IDEA-JNC` · SID S4H · client 100 · tier DEV · 로그온 언어 JA).
  2026-11-10 접속 정보 갱신 뒤 `ReloadProfile` → `GetSystemInfo`로 접속 확인.
- **요청**: 소유자 한 줄 — 「구매오더 목록 ALV 조회」. 소유자가 사람으로 붙은 attended 실행.
- **경로**: 설치본 플러그인 0.13.0의 `sapkit:create-program` 스킬 → 지시서 그대로.
  구현은 기본값대로 위임(`sapkit:sap-worker`), 검토는 새 맥락 `sapkit:sap-reviewer`.
- **산물**: `ZMMR10`(실행 프로그램) + 인클루드 6(`T`·`C`·`S`·`A`·`F`·`_TST`) — `$TMP` · 이송 없음.
  절차형 · SALV 전체화면 · EKKO/EKPO/EKET/LFA1 직접 조회 · 미입고 납품일정(지연 순) ·
  구매조직 표시 권한(`M_BEST_EKO`) 필터 · 더블클릭 ME23N.
- **종결 상태: `COMPLETE`** — 7객체 되읽기 대조 동일(수정 반영 뒤 재확인) · 구문 clean ·
  비활성 0 · ATC 오류 0/경고 0 · 독립 검토 PASS(MINOR 8 — 4건 코드 수정, 4건 기록).
  **한계**: 단위 시험 5개(수용 예시 A1~A5)는 **실행되지 않았다**(아래 결함 ②) · 실데이터로
  돌려 본 적 없음 · 텍스트 풀 미입력(소유자가 SE38에서 넣는다).
- 실행 기록(비추적): 사용자 프로젝트 쪽 `.sapkit/program/ZMMR10/` — 설계서 · 승인(해시 결속) ·
  검증 · 검토 요청/결과 · 완료 보고.

## 2. 판I·판H 시험대 질문에 대한 답 (HANDOFF 「다음 작업」 ⑴ · ⓪-b)

## 3. 결함 · 소견

### ① 플러그인 준비물 미설치를 아무도 먼저 보지 않는다 — 절차 결함 (가장 무겁다)

- **사실**: IDES에 `ZSAPKIT_ADT_UTILS`(화면·GUI 상태·텍스트 요소 도구가 거치는 FM)와
  공용 ALV 클래스 7종(`ZCL_SAPKIT_CM_*` 등)이 **없다**(`SearchObject` 0건 · 대조로 표준 클래스는
  정상 검색). 프로파일의 RFC 통로 키는 비어 있어 기본값 `odata`(게이트웨이 서비스 필요)다.
- **사실**: `create-program` 0단계는 이것을 확인하지 않는다. 인터뷰는 OOP · 전체 화면 ALV를
  권장안으로 내밀고, 막힌다는 사실은 기술 묶음 도중 메인이 따로 조사해서야 드러났다.
  4단계 5번에 「FM이 없으면 SKIPPED」 규칙이 있으나 **너무 늦다**(이미 승인된 설계가 화면을 전제).
- **결과**: 소유자는 절차형 · SALV · 텍스트 수기 입력으로 설계를 낮췄다.
- **뿌리(사실 · 같은 날 추가 확인)**: setup을 돌렸어도 같았다.
  - **`setup.md`는 `install-sap-assets`를 한 번도 부르지 않는다.** 원본 마법사의 9단계(설치)는
    이식 때 별도 절차로 떨어져 나갔다(`MIGRATION-MANIFEST.md` — wizard-step-09 → `install-sap-assets.md`).
  - 그 절차를 부르는 스킬도 없다. 링크하는 곳은 `troubleshooting.md`의 처방 문구와 `create-program` 4단계 SKIPPED 규칙뿐이다.
  - setup 자가 점검(troubleshooting §1)에 준비물 층(Layer 4)이 있기는 하다. 그러나 setup은 비밀번호를 비운 채 끝나므로 그 층은 늘 「연결 미준비 → SKIP」이다.
  - ⇒ **새 SAP 시스템의 사용자에게 설치를 권하는 입구가 제품 어디에도 없다.**
- **심각도(판단)**: 안전 결함 아님 — 잘못 쓴 것 · 데이터 위험 없음, 대체 경로(SKIPPED · SALV)로 끝까지 간다.
  제품 결함으로는 크다. 기본 권장(OOP · 전체 화면 ALV)과 화면 · GUI 상태 · 텍스트 도구가 새 시스템마다 막히고, 고칠 입구가 없다.
- **처분 후보**:
  - setup에 설치 단계를 되살린다(DEV tier · 소유자 승인 · SE37 원격 호출 표시는 사람 몫).
  - 설치 상태 탐침을 `create-program` 0단계에도 둔다(`SearchObject` 2~3회 → 권장안을 거르고, 미설치면 설치 제안 한 줄).
- **처분(2026-11-11 · D-167 · 플러그인 0.13.1)**: 두 후보 모두 집행했다.
  - setup 7단계 「SAP 쪽 준비물」을 신설했다.
  - `create-program` 0단계 4번에 탐침 둘을 두었다. 하나는 ALV 클래스 검색, 다른 하나는 RFC 통로를 실제로 지나는 읽기 1회다.
  - SAP 실기는 0이다.
- **재처분(같은 날 · D-168)**: 소유자가 두 가지를 짚었다. 대부분의 사용자는 MCP를 아예 연결하지 못한다.
  그리고 생성 프로그램이 미리 깔린 공용 클래스에 기댈 이유가 없다.
  - OOP 표본을 표준 SAP 클래스만으로 다시 썼다. 생성 프로그램은 이제 아무것도 미리 설치할 필요가 없다.
  - 그래서 D-167의 ALV 부분은 걷어냈다: setup 7단계의 ALV 행 · 「ALV 클래스만」 선택지, 0단계의 ALV 클래스 탐침과 「없으면 절차형 권장」 거르기.
  - 남은 준비물은 RFC 통로(화면 · GUI 상태 · 텍스트를 MCP로 쓰는 길) 하나다. 연결이 없는 사용자에게는 애초에 필요 없다.

### ② `RunUnitTest`는 프로그램 안 시험 클래스를 돌리지 못하고, 그런데도 성공이라고 답한다 — 엔진 결함

- **사실**: `RunUnitTest(container ZMMR10 / LTCL_HELPER)` → `success: true` · `run_id` 발급 ·
  `GetUnitTestResult` → **빈 `aunit:runResult`**. 엔진이 실행 주소를 항상
  `/sap/bc/adt/oo/classes/<name>`으로 만든다(`sapkit-engine/src/tools/runtime/internal/unitTestRuns.ts:129`).
- **결과**: 시험 5개는 활성 상태로 있으나 기계로 실행되지 않았다 → 검증 기록 `unit_test: SKIPPED`(사유 기재).
- 결함 대장 등재: `engine-backlog.md` §2-c ①. (§1의 13-2 「침묵 무결과」가 해소된 것은 클래스 대상이다 — 이것은 다른 갈래다.)

### ③ 절차형의 시험 — 지시서가 앞뒤로 다르게 말한다 — 절차 결함

- **사실**: 기술 7번은 시험 범위를 묻고(권장: 수용 예시 → 시험), 작법 쪽지는 절차형도
  `LCL_HELPER`로 빼서 시험하라고 하는데, 5단계는 「절차형 = 시험 클래스 없음 → 건너뜀」이라 적는다.
- **처분 후보**: 5단계 건너뜀 조건을 「시험 범위 없음」으로 좁히고 절차형 `_tst`를 정식 경로로.

### ④ 번호 객체 이름의 자릿수 — 쪽지에 폭이 없다 — 쪽지 결함

- **사실**: 메인이 `ZMMR10`으로 이름을 정했다. `naming-conventions.md` §1은 `{NN}`을
  **다섯 자리**(`00010`)로 정한다 → 맞는 이름은 `ZMMR00010`. 리뷰어가 MINOR로 잡았다.
- **원인(사실)**: 지시서에 실린 작법 쪽지는 `Z{MODULE}{TYPE}{NN}` · 「last + 10」만 싣고
  **폭을 싣지 않는다** — 판L이 압축하며 잃은 세부다. 메인은 쪽지만 보고 정했다.
- **처분 후보**: 쪽지 사내 규칙 줄에 「`{NN}` = 0 채움 5자리(`00010`)」를 덧붙인다(정본 → 사본 게이트).

### ⑤ 착수 안내의 권한 문장이 이 프로젝트에서는 사실과 달랐다 — 절차 결함(작음)

- **사실**: 착수 안내는 「삭제 · 이송 · 실행 · 실데이터는 허용해도 따로 묻는다」고 말하게 돼 있다.
  그런데 이 레포의 `.claude/settings.local.json`에는 **원래부터** 삭제 · 이송 · 런타임 도구
  42항목이 허용돼 있었다(병합은 3항목만 추가). 메인이 병합 뒤 세어 보고 소유자에게 정정했다.
- **처분 후보**: 안내 문장을 말하기 전에 기존 허용 목록에서 제외 계열 항목을 세고, 있으면 그 사실을 말한다.

### ⑥ 인클루드 설명문이 검색 결과에서 한 칸씩 밀려 보인다 — 원인 미확정 (관측 등재)

- **사실**: 작업자가 넘긴 `description`은 호출 기록상 객체마다 올바랐다(T·C·S·A·F·_TST 순).
  `SearchObject` 결과(엔진이 전달하는 SAP 원문 XML 그대로)에서는 **알파벳 순으로 한 칸씩 밀린 값**이
  보이고, `ZMMR10_TST`의 값은 어디에도 없다. 메인 프로그램도 검색 결과는 기본값, `ReadProgram`
  메타데이터는 넘긴 값이다. 같은 모양이 **남의 객체**(`ZMM_PO_LOADER_*` · `ZMM_PRACTICE_001_*`)에서도 보인다.
- **가설**: SAP 검색 쪽 설명 출처의 문제(엔진 무관)일 가능성이 높다. 인클루드 설명을 읽는 도구가 없어 저장값은 미확인.
- 결함 대장 등재: `engine-backlog.md` §2-c ②(관측만).

### ⑦ 그 밖의 관측

- **질문 부담**: 소유자가 두 번 위임을 요청했다(「알아서 좀 하면안되?」 · 「대충 만들어줘」).
  시험 목적 실행에서는 묶음 6개 + 파내기가 무겁게 읽힌다는 신호다. 「서둘러」 모드가 지시서에 없다.
- **메인의 말실수 1**: 공용 ALV 클래스가 「이 시스템에 없다」고만 물어 소유자가 「플러그인에
  템플릿이 있는 것 아니냐 · 이번 수정이 반영됐는지 수상하다」고 되물었다. 정확한 말은
  「플러그인은 갖고 있고, 이 SAP에 설치가 안 됐다」였다(①과 같은 뿌리).
- **로그온 언어 JA**: 텍스트 마스터 언어가 J로 잡힌다. 한국어 텍스트는 소유자 입력에 맡겼다.
- **ATC가 잡고 리뷰가 잡은 것**: 해시 표 WHERE 순회(ATC 경고 2) · 권한 제외 건수가 「데이터 없음」에
  가려짐 · 「지연분만」 사후 필터 · 아이콘 열 제목 — 모두 코드로 고쳤다.
