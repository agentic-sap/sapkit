- C-01 규칙 6 (E1-07 · E1-20) → 통과.
  판정 기준은 괄호 「cl_salv_table=>factory 의 cx_salv_msg 를 빈 CATCH 로 삼키면 위반 · 메시지 출력이나 전파면 통과」다
  (과제 파일 §3 머리말 「규칙 번호 뒤 괄호는 채점자용 판정 기준」 · 지침 §3 · §5). 두 행 모두 CATCH cx_salv_msg INTO lx_msg
  뒤 MESSAGE 를 낸다(E1-07 80-81 · E1-20 146-147) → 괄호 기준 통과.
  A 가 §5-A ⓐ 로 더한 「주석만 · RETURN 만인 CATCH cx_salv_not_found 도 삼킴」은 괄호 기준 밖의 확장이다. 규칙 86 본문
  「Swallowing one silently is never acceptable」만으로 봐도: E1-07(130-131)은 「열이 출력 구조에 없으면 DDIC 제목 유지」라는
  복구 경로를 주석으로 적은 폴백이라 조용한 삼킴이 아니고(clean-code.md:89 — 복구 경로가 명시 · 문서화된 경우), E1-20(178-179)은
  RETURN 만 있어 본문만으로는 더 가까운 사례다. 그러나 두 행 모두 판정은 괄호 기준으로 통과이고, 그 CATCH 는 기록만 남긴다.
  갈림의 원인은 괄호가 cx_salv_msg 하나만 가리키는 데 있다(② 참조).
- C-02 규칙 7 (E1-08) → 위반 (7@93).
  규칙 7 에는 괄호 기준이 없어 인용 원문이 기준이다 — 「Name tests for given-when-then — is_released_returns_true_when_
  status_is_freigegeben, never test01 or test_ok」. 예시 이름은 행위(is_released) · 기대 결과(returns_true) · 조건(when_status_is_…)
  을 담고, test01 · test_ok 는 금지의 예시이지 금지의 전부가 아니다. 93~99 의 normal_discount · full_discount · zero_discount ·
  negative_gross · percentage_too_high · percentage_negative 는 입력 상황(given)만 적고 무엇을 하는지(when) · 무엇이 나와야 하는지
  (then)가 없다. 「무의미한 이름만 센다」(A §5-A ⓓ)는 규칙 본문의 긍정 요건(given-when-then 으로 짓는다)을 지우는 읽기라 택하지
  않았다. rounding_to_cents 는 기대 동작을 담아 경계에 있으나 나머지 여섯이 위반이라 결과는 같다. 대표 줄 = 첫 테스트 메서드 선언 93.
- C-05 규칙 10 (E1-09) → 통과.
  규칙 10 에도 괄호 기준이 없다 — 「Always check sy-subrc, or catch the class-based equivalent」. A · B 모두 「SELECT … INTO TABLE
  의 결과 테이블 IS INITIAL 검사」를 sy-subrc 검사의 등가로 인정했고(§5-A 셋째 항 · §5-B 둘째 항 — E1-07 · E1-17 의 규칙 2 는 이
  등가로 두 채점자가 함께 통과시켰다), 갈린 것은 거리(A: 직후만 · B: 어디서든)다. 규칙 문언에는 「직후」 요건이 없다. 등가가 성립하는
  조건은 「SELECT 와 검사 사이에 결과 테이블의 비어 있음 여부가 바뀌지 않는 것」인데, E1-09 는 SELECT(56-59) 뒤 SORT gt_cust(61)와
  gt_cust 를 읽기만 하는 LOOP(63-68 · COLLECT 대상은 gt_cnt)만 지나므로 78 의 gt_cust IS INITIAL 은 sy-subrc <> 0 과 같은 사실을
  검사하고, 결과에 따라 행동한다(79-80 「없음」 메시지 · RETURN — 출력 전). 따라서 통과. 파생 테이블 검사(E1-02 의 gt_out)와는
  다르다 — 그쪽은 두 채점자가 함께 위반으로 두었고 갈린 행이 아니다.
  주의: 규칙 문언만 엄격히 읽으면 sy-subrc 검사 자체는 이 행에 없다. 등가 인정은 두 채점자가 공유한 규약이고, 갈리지 않은
  행(E1-07 · E1-17 규칙 2)이 그 위에 서 있으므로 제3 판정이 그 전제를 뒤집지 않았다 — 등가의 인정 여부가 아니라 거리만 판정했다.
- C-01 규칙 5 대표 줄 (E1-20) — 위반 자체는 A · B 일치(AUTHORITY-CHECK 127-129 가 EKKO 읽기 뒤 행별 사후 필터 111-117). 줄은 A 88

  88 을 대표 줄로 뒀다. 정의상 갈림이 아니므로 어느 쪽이어도 결과는 같다.
- 갈리지 않은 번호는 A · B 가 일치한 값을 그대로 두었다(E1-07 1~5 · 7 / E1-08 1~6 · 8~10 / E1-09 1~9 · 11 / E1-20 1~5 · 7). 각 행의

  E1-09 7.40+ 구문 없음 · abap_bool 은 7.02 에서 TYPE-POOLS 없이 쓸 수 있음).
- 결과가 B 의 4행 판정과 전부 같아졌다. 이는 각 번호를 문언으로 정한 결과이지 B 를 따른 것이 아니다 — 근거는 위 항목마다 적었다.
  셋 가운데 둘(규칙 6 · 규칙 10)은 「괄호 기준 또는 문언에 없는 요건을 더하지 않는다」는 같은 원리에서 나왔고, 하나(규칙 7)는
