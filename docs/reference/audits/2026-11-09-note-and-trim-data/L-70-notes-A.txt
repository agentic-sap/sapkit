① 규약 적용 메모 — §5-A 를 이 묶음에 어떻게 적용했는가 · 판단이 갈린 적용
-------------------------------------------------------------------------------
- 번호 규칙만 계수. 목록 밖 작법(배너 규칙이 없는 C-01 · C-04 · C-05 의 배너 · 정적 메서드 · 신문법 ·
  텍스트 풀 참조 · LEAVE LIST-PROCESSING · itab 중첩 루프 · READ TABLE 뒤 sy-subrc)은 ③에 미계수로만 적었다.
- 검사기 오류급은 20행 전부 0(기계 결과 그대로 · 뒤집은 것 없음). 따라서 이 묶음의 통과/불통과는 전적으로
  general_rules 판정으로 갈렸다. 「한 줄 한 문장」(C-01 규칙7 · C-04 규칙7 · C-02 규칙10)은 검사기와 겹치는
  항목이라 코드에 .-체인이 없음을 눈으로 확인하고 전부 통과로 두었다.
- sy-subrc 등가(§5-A 셋째 항 — 「SELECT ... INTO TABLE 직후 대상 테이블 IS INITIAL」) 경계를 이렇게 그었다:
  · 인정 — SELECT 가 FORM 의 유일(또는 마지막) 실행문이고, 호출부가 PERFORM 바로 다음 문장에서 그 대상 테이블을
    IS INITIAL 로 검사: E1-07(52) · E1-17(49). 제어 흐름상 SELECT 직후와 같다고 봤다.
  · 불인정 — 검사 대상이 파생 테이블(E1-02: gt_item 을 루프로 합산한 gt_out 을 40에서 검사) · 검사가 SORT · COLLECT
    루프 · 다른 FORM 을 지난 뒤(E1-09: write_list 의 78). 둘 다 위반으로 셌고 remarks 에 「판단갈림」으로 표시했다.
    제3 판정이 이 경계를 달리 그을 수 있다.
- ⓐ C-01 규칙6 — 괄호 기준(cx_salv_msg 처리)에 더해 주석만 · RETURN 만으로 끝나는 CATCH cx_salv_not_found 를
  삼킴으로 계수: E1-07(130-131) · E1-20(178-179). E1-17 은 세 예외를 한 CATCH 에서 메시지로 처리해 통과.
  E1-11 은 cx_salv_not_found 를 잡는 자리 자체가 없다(열 제목 설정 없음).
- ⓑ C-02 규칙4 — 파일 안 모든 클래스에 FINAL 요구. E1-08 의 지역 예외 클래스 lcx_discount_input(9-11)이
  FINAL 아님 → 계수. E1-05 · E1-15 는 예외 클래스 포함 전부 FINAL. E1-19 는 예외 클래스가 파일 밖(가정한 전역)이라
  그 클래스는 판단 대상이 아니고, 파일 안 두 클래스는 FINAL.
- ⓒ C-02 규칙5 — 공개 시그니처에 쓰인 공개 TYPES(ty_amount · ty_percentage 류)는 미계수(4행 전부 해당).
  이 묶음에서 추가로 그은 경계: 규칙5 괄호가 「CALCULATE 와 생성자 외의 멤버」라 CALCULATE 를 가진 클래스를
  겨눈다고 읽고, 예외 클래스의 공개 READ-ONLY 속성 · 상수 · get_text 재정의(E1-05 4-10 · E1-08 14-25 · E1-15 6-10)는
  규칙5 로 세지 않았다. 호출자가 거부 사유를 읽어야 하는 입증된 필요이기도 하고, clean-code-oop.md:45 의
  「생성자에서 할당되는 immutable READ-ONLY」 패턴에 든다. 제3 판정이 달리 볼 수 있어 적어 둔다.
- ⓓ C-02 규칙7 — 무의미한 이름(test01 · test_ok 류)만 계수. E1-08 의 normal_discount · full_discount ·
  negative_gross · percentage_too_high 등은 then 부가 없는 시나리오명이지만 무의미하지는 않아 미계수
  (remarks 에 판단갈림). E1-05 · E1-15 · E1-19 는 given/when/then 또는 결과 서술이 있어 통과.
- C-01 규칙5 「SELECT 앞」 — E1-20 은 AUTHORITY-CHECK(127)가 있으나 EKKO 를 두 번 읽은 뒤(88 COUNT · 100 본 읽기)
  행별 사후 필터로 수행한다. 괄호 문언 「SELECT 앞에 없으면 위반」대로 위반으로 셌다(권한 없는 조직의 행을
  이미 읽어 온 뒤의 필터). 판단갈림 표시. E1-11 은 T024E 로 조직을 뜬 뒤 조직별 검사 → 범위로 WHERE 에 넣어
  SELECT 앞을 충족한다.
- C-04 규칙2 — E1-02 는 품목 전 행을 읽어 ABAP 루프에서 합산(SHKZG 부호 처리 사유를 배너에 명시) → 괄호 문언대로
  위반. 함께 규칙의심 1건을 ②에 올렸다. E1-04 · E1-12 · E1-18 은 SUM/COUNT + GROUP BY.
- C-05 규칙8 — COUNT(*) AS 별칭(E1-01 78)은 집계 별칭이지 CASE/CAST/COALESCE 가 아니라 통과.
- 줄 번호 — 위반이 드러나는 대표 줄 하나. AUTHORITY-CHECK 부재 · 사후 수행은 보호 대상 테이블의 첫 SELECT 줄
  (E1-20 은 88), 배너는 첫 배너 줄, FINAL 누락은 CLASS DEFINITION 줄, 빈 CATCH 는 CATCH 줄, sy-subrc 부재는
  그 SELECT 줄.
- 행 간 참조 없음 — 각 행은 자기 general_rules 와 코드로만 판정했다. 같은 과제의 다른 행과 맞추지 않았다.

② 규칙의심 목록 (규칙은 고치지 않는다 — 표시만)
------------------------------------------------
- E1-02 · C-04 규칙2 — 괄호는 「품목 전 행을 읽어 ABAP 루프에서 합산하면 위반」으로 예외가 없다. 그런데 MSEG 수량을
  SHKZG(차/대변 지시자)로 상계하려면 SELECT 안 CASE(Open SQL 식 — abap-release-reference.md:68 기준 7.50+)가
  필요하거나 부호별 두 SELECT 를 합쳐야 한다. 7.50 미만이거나 CASE 를 피하는 코드가 부호 상계를 ABAP 루프로
  하는 것은 실무상 사유가 될 수 있는데 규칙이 이를 가르지 않는다. 판정은 규칙 글자대로 위반.
