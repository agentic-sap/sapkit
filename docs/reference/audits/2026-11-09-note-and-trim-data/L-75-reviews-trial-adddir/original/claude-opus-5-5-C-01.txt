# §8 리뷰: ZJUDGE_C01 (Procedural, 7.58)

Paradigm이 Procedural이므로 `clean-code.md`와 `clean-code-procedural.md`만 읽었습니다. 구조 비교에 쓸 템플릿 `templates/procedural-sample/main-program.abap`은 해당 경로에 파일이 없어서 열지 못했습니다. 그래서 구조 항목은 `clean-code-procedural.md` § Mandatory Main Program Template의 본문을 기준으로 판정했습니다.

## 어긋남

```
메인 프로그램 구조 (이벤트 블록 배치) | 45–48, 52–57 | INCLUDE가 없는 것은 과제가 단일 파일을 요구했으므로 정당한 차이로 봄. 그 외 두 가지가 규정과 다름: (1) END-OF-SELECTION 블록이 없고 ALV 출력이 START-OF-SELECTION 안에 있음, (2) 빈 결과 처리(IF/MESSAGE/RETURN)와 p_max 검증이 FORM이 아니라 이벤트 블록 안에 직접 쓰여 있음("Do not pull FORM logic inline into events"). spec.md에 근거가 없으므로 규정상 MAJOR. 템플릿 원본과는 대조하지 못함

최신 구문 (ABAP_RELEASE 7.58) | 61–67 | 구식 Open SQL 문법을 씀: 필드 목록에 쉼표가 없고 호스트 변수에 @ 이스케이프가 없음(gt_data, p_max, s_ekorg, s_bedat). 7.58이면 strict 문법을 써야 함 → SELECT ebeln, bukrs, … FROM ekko WHERE ekorg IN @s_ekorg AND bedat IN @s_bedat ORDER BY ebeln INTO TABLE @gt_data UP TO @p_max ROWS.
```

## 참고 (어긋남으로 세지 않음)
- **검사기 analyze의 `double_space` 12건**은 선언과 대입을 정렬하려고 넣은 공백입니다. 오히려 정렬 일관성을 지킨 결과이므로 위반이 아닙니다.
- **lint의 `lo_`/`lx_` 4건**은 `naming-conventions.md` 패턴(`l[vstrc]_`)에 걸린 것입니다. §8의 g/l 구분 항목은 충족하고, 이 파일은 이번 범위에서 읽지 않았으므로 §8 결과에는 넣지 않았습니다. FORM 파라미터 접두사 `io_`/`iv_`(OOP식 명명)도 같은 이유로 판정을 보류했습니다.
- **충족 또는 해당 없음:**
  - 충족: `SELECT *` 없음, LOOP 안 SELECT 없음, ABAP_BOOL/abap_true 사용, 긍정형 조건, 명시적 타입의 전역 테이블, 주석 처리된 코드나 디버그 문 없음, FORM 파라미터 타입 지정, EXIT/STOP 없음.
  - 해당 없음: 백틱 문자열(텍스트 심볼 fallback은 작은따옴표 문법이 필수), 2차 키(EKKO 결과를 비키 필드로 다시 조회하지 않음), DEC 산술, 대사 로직, PBO/PAI, 화면 접미사, 테스트.
