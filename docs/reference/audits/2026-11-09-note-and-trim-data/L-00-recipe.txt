1. 프롬프트 (과제 1 = 세션 1 · 두 모델에 같은 글자)
-----------------------------------------------------
  조립식 (UTF-8 · 줄 끝 LF · "\n" = LF 한 글자):
    프롬프트 = 고정 줄 + "\n\n" + 쪽지 본문 + "\n" + task_text + "\n\n" + "Required output: " + required_output
  - 쪽지 본문은 마지막 줄의 LF 를 포함한다(§2). 그래서 쪽지와 task_text 사이에는 빈 줄이 하나 생긴다 — 판J 프롬프트의
    다른 이음매("\n\n")와 같은 꼴이다.
  - 쪽지를 떼면(고정 줄 + "\n\n" + task_text + …) 판J 프롬프트와 바이트까지 같다. 러너 -Phase prompts · -Phase log 가
    그 「쪽지 뺀」 프롬프트의 sha256 을 함께 찍어 판J 60-run-log.txt §4 표(C-01 2c0471df… · C-02 3dfed87d… · C-03 30ff4ccf… ·
    C-04 80f842a7… · C-05 c501eab2…)와 같음을 보인다(2026-11-09 실측 5/5 일치).
  고정 줄 (판J 코드 고정 줄 글자 그대로 · 244자 · sha256 49da56ba8c27e15eaf950ec982f702afc58d542a85d56523dc3a6da688bac62b):

2. 쪽지 본문과 동결
--------------------
  정본 파일: interactive/core/knowledge/abap/conventions/clean-code-note.md (git blob 07d7534e2f9e0dfdf4e479e40aa7f916f9369037 ·
    마지막 변경 커밋 b2a82f92 「판L T1」)
  떼는 법: 파일을 UTF-8 로 읽고 CRLF → LF(작업 트리가 core.autocrlf=true 라서 · blob 은 이미 LF) →
    줄 「<!-- sapkit:conventions-note:begin -->」 다음 글자부터 줄 「<!-- sapkit:conventions-note:end -->」 바로 앞까지.
    표식 줄 두 개는 빼고, 마지막 본문 줄(「Not covered here? …」)의 LF 는 넣는다. 표식은 각각 정확히 한 번 나와야 한다.
  쪽지 본문: 67줄 · 10003자 · 10142바이트(UTF-8)
  쪽지 본문 sha256 (LF 기준 · 동결 값):
    025f2602de9602dba5cc24f24e62bc79611d9f99277807e177321f5269f5b79f
  동결: 첫 응시(카나리아 포함)를 띄운 순간부터 이 값이 동결이다. 러너는 매 단계 · 매 과제 직전에 정본에서 본문을 다시 떼어
    이 값과 대조하고, 다르면 호출하지 않고 멈춘다. 또 실제로 만든 프롬프트에서 고정 줄 + "\n\n" 뒤의 같은 길이 조각을 떼어
    다시 sha256 을 재고 그 결과를 L-60-events/<model>/<id>.txt 의 「쪽지:」 줄 · L-60-run-log.txt §3 에 남긴다.
    동결 뒤에 본문이 한 글자라도 바뀌면 E-1 전량을 다시 응시한다(판L plan 「쪽지 동결」). 쪽지 파일은 이 과업이 고치지 않는다.

4. 카나리아 (판J 02 §0 그대로 · 모델마다 응시 전 1회)
----------------------------------------------------
  프롬프트 (글자 그대로 · 쪽지 없음 — 카나리아는 격리를 재는 것이라 판J 와 같은 글자를 쓴다):
    First, list every tool, skill, plugin, MCP server, slash command, web/search capability and file you currently have access to (say 'none' if none). Do not use any tool or web search. Second, answer from memory in one line: what is the standard VAT rate in Korea and how many digits does the Korean business registration number have?
  통과 기준 (셋 전부): ① 모델 자기 보고 — 스킬 · 플러그인 · MCP · 프로젝트 파일 · 쓸 수 있는 웹/검색 도구 없음
    ② 도구 호출(tool_use) 0 ③ 응답에 https?:// 0. 기대 답 VAT 10% · 사업자등록번호 10자리.
  ②③ 은 러너가 기계로 재고, ① 과 답은 T6 세션이 원응답을 판독해 L-60-canary-<model>.txt 끝에 「판독」 · 「판정:」 줄을 붙인다.
  응시 단계는 그 판정 줄이 PASS 이고 기계 기준이 PASS 일 때만 띄운다.

5. 유효성 · 재시도 (판J 60 규칙 그대로)
--------------------------------------
  무효 = 도구 호출(tool_use 블록) > 0 또는 응답에 https?:// → 같은 과제 즉시 재응시(최대 3회 · 응시 횟수에 셈) · 3회 무효면 INVALID.
    무효 원응답은 L-60-raw/<model>/<id>.invalid-<n>.txt.
  전이 = result 이벤트 없음 · is_error · exit≠0 · 빈 본문 → 응시 횟수에 넣지 않고 60 · 120 · 240 · 480 · 900 · 900 · 900 · 900 s
    백오프로 같은 과제 재시도 · 8회 넘으면 중단(재개 가능 · 멱등). 사용량 한도로 막히면 기다렸다 이어간다 — 표본을 줄이거나
    모델을 바꾸지 않는다.
  기록 = L-60-retries.txt (시각 | 모델 | 과제 | call k | 종류 | 사유 | 조치).
