Internal table 타입이 접근 패턴에 맞고 DEFAULT KEY 없음 | 16, 87–88 | **MAJOR**: `ty_t_customer`가 `STANDARD … WITH DEFAULT KEY`로 선언되어 있습니다. 그런데 이 테이블은 87–88줄에서 국가마다 `LOOP … WHERE land1 = …`로 반복 접근됩니다. STANDARD 테이블이라 WHERE가 키로 최적화되지 않고, 국가 수만큼 테이블 전체를 훑게 됩니다(국가 수 × 고객 수). `SORTED TABLE … WITH NON-UNIQUE KEY land1 kunnr`로 바꿔야 합니다(7.02에서 사용 가능). 이렇게 바꾸면 50줄의 `SORT`도 필요 없어집니다.
Internal table 타입이 접근 패턴에 맞고 DEFAULT KEY 없음 | 22, 64 | **MINOR**: `ty_t_count`도 `WITH DEFAULT KEY`입니다. `COLLECT`가 기대는 키(문자형 필드인 land1)가 선언에 드러나지 않고 암묵적으로 정해집니다. `HASHED … WITH UNIQUE KEY land1`이나 `SORTED … WITH UNIQUE KEY land1`로 키를 명시해야 합니다(SORTED로 하면 66줄 `SORT`도 필요 없음).

## 확인했고 문제 없는 항목
- **SQL**: `SELECT *` 없음, LOOP 안 SELECT 없음, 타입이 명시된 테이블로 SELECT, SORT/DELETE ADJACENT는 모두 `BY` 지정. KNA1은 마스터 테이블이므로 secondary key / `COUNT(*)` 사전 점검 규칙은 적용 대상이 아닙니다.
- **Boolean, 비율 연산, 대사(null→0)**: 해당 코드가 없습니다.
- **7.02 문법**: 7.40 이후 문법은 쓰이지 않았습니다.
- **문자열**: 백틱이나 템플릿이 필요한 STRING 값이 없습니다. 텍스트 심볼 `'…'(nnn)`은 문법상 작은따옴표를 써야 하므로 위반이 아닙니다.
- **기타**: 사용된 statement 가운데 sy-subrc를 확인해야 하는 것은 SELECT뿐이고, 처리 내용은 위에 적었습니다. EXIT/STOP으로 오류를 처리하는 곳 없음(78줄 `RETURN`은 guard clause). PBO/PAI와 화면 suffix는 해당 없음. 과제가 테스트를 요구하지 않으므로 LCL_HELPER도 해당 없음.

## 참고
- **검사기 결과**: `analyze`가 낸 `double_space` 9건(20·25·58·63·73·86줄은 정렬용 공백, 51·67·96줄은 ENDFORM 꼬리 주석 앞 공백)은 의도한 정렬이라 오탐으로 보고 표에 넣지 않았습니다. 반대로 위의 DEFAULT KEY와 접근 패턴 문제는 검사기가 하나도 잡지 못했습니다.
- **템플릿 대조 불가**: §8이 기준으로 삼는 `knowledge/abap/templates/procedural-sample/main-program.abap` 파일이 작업 디렉터리에 없습니다. 그래서 구조 항목은 clean-code-procedural.md의 설명만 보고 판단했습니다. 이벤트 블록 순서처럼 템플릿에 따라 달라지는 판정은 템플릿을 찾으면 다시 확인해야 합니다.
- **§8 밖 기능 문제**: `TOP-OF-PAGE`의 열 제목(100줄)은 리터럴 길이만큼만 출력됩니다. 그래서 상세 줄의 열 너비(kunnr 10 / name1 35 / ort01 35 / land1 3)와 맞지 않습니다. 열 위치를 지정해 출력해야 합니다(`AT pos(len)` 또는 `UNDER`).
