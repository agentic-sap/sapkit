### 적용 대상이 아닌 항목
- **Main program 템플릿 일치**: 과제 산출물이 REPORT가 아니라 전역 클래스 한 파일이라 비교할 대상이 없습니다. 이 구조는 과제 설명이 정한 것이어서 spec.md에 따로 적지 않은 것을 위반으로 보지 않았습니다.
- **해당 구문이 없는 항목**: 코드에 SELECT, sy-subrc를 세팅하는 문장, 내부 테이블, SORT/DELETE ADJACENT, boolean, 대사(reconciliation) 출력이 없습니다.

### 위반이 없다고 확인한 항목
- **좁은 DEC 필드 오버플로**: 결과는 gross 이하이고 ty_amount(p 15)에 들어가므로 COMPUTE_BCD_OVERFLOW가 날 수 없습니다. 퍼센트 값은 비교에만 쓰고, 계산은 decfloat34로 합니다.
- **7.58 문법**: `RAISE EXCEPTION NEW`, `CONV decfloat34`, `round( mode = )`는 모두 7.58 이하에서 쓸 수 있습니다.
- **기타 클래스 규칙**: FINAL, 메서드 길이와 파라미터 수, RETURNING, `NEW #`, 120자 한도, 주석 처리된 코드나 디버그 문장 없음을 모두 확인했습니다. 122줄은 빈 CATCH지만, 이유를 적은 주석이 있으므로 규칙상 허용됩니다.

### 검사기 출력에 대한 판정
- **double_space 14건은 위반이 아닙니다.** 모두 TYPE, 파라미터, FOR TESTING 열을 맞추려고 넣은 의도적인 공백이고, §8은 일관된 정렬을 요구합니다.
- **두 번째 항목(public 시그니처가 로컬 타입을 참조하는 문제)은 검사기에 안 걸립니다.** `parse`는 토큰만 나누는 도구라 이런 오류를 보지 못합니다. lint와 analyze도 이 문제를 보고하지 않았습니다.
