## 위반 없음 또는 해당 없음

- **SELECT 관련:** `SELECT *` 없음(필드 목록 명시). LOOP 안 SELECT 없음. 인라인 `@DATA(...)` 대신 명시 타입 테이블 `gt_header` 사용.
- **테이블 타입:** STANDARD WITH EMPTY KEY지만 ALV에 순차 출력만 하므로 의도에 맞음. 키 없는 SORT나 DELETE ADJACENT DUPLICATES 없음. DEFAULT KEY 없음.
- **보조 키:** 기본 키가 아닌 필드로 다시 접근하는 곳이 없어 필요 없음.
- **STRING:** STRING 변수가 없음. 작은따옴표 리터럴은 모두 텍스트 심볼 `'…'(xNN)`이거나 CHAR 타깃(`lvc_fname`)이라 백틱을 쓸 수 없거나 쓸 필요가 없음.
- **Boolean·조건:** Boolean은 `abap_true`만 사용. 조건은 긍정형이고 빈 IF 분기 없음.
- **릴리스·코드 정리:** 7.58 범위 안의 문법만 씀. 주석 처리된 코드나 디버그 문 없음. 비율 연산과 대사(reconciliation) 로직 없음.
- **전역·지역:** 전역은 상단에 모여 있음. g/l 접두어로 구분되고 shadowing 없음. 파라미터는 모두 타입이 지정되고 USING으로 입력함.
- **기타:** 화면에 묶인 FORM과 PBO/PAI가 없음. CALL FUNCTION 없음. 과제가 테스트를 요구하지 않아 LCL_HELPER도 해당 없음.

## 체크리스트 행은 아니지만 참고할 점

- **27행 `TEXT-b01`:** 과제가 텍스트 풀을 금지하므로 프레임 제목이 비어 나옵니다. `'…'(c01)` 형태와 달리 대체 리터럴이 없습니다.
- **1–5행, 21–23행 배너 주석:** `clean-code.md` § Comments의 "No comment banners"에 걸립니다.
- **50–51행 `TYPE 'S' DISPLAY LIKE 'I'`:** 과제의 "information message" 요구에 비해 상태 표시줄 메시지일 뿐입니다. 정보 팝업을 의도했다면 `TYPE 'I'`가 맞습니다.
- **검사기 출력 평가:**
  - lint의 `lo_` 경고 2건은 §8 위반이 아닙니다. `clean-code.md`가 지역 변수의 `lo_` 접두어를 허용합니다.
  - analyze의 `double_space` 7건은 정렬용 공백이라 위반이 아닙니다.
  - 위의 실제 어긋남 7건은 검사기가 하나도 잡지 못했습니다.
