**해당 없음 / 통과**
- **해당 없음:**
  - 메인 프로그램 템플릿 항목: REPORT가 아닌 전역 클래스라서
  - SELECT, sy-subrc, 내부 테이블, 보조 키, COUNT(*), Boolean, 대사(reconciliation) 관련 항목
  - 테스트 더블: 의존성이 없음
- **통과:**
  - 메서드: 17줄, 파라미터 2개, RETURNING
  - 전역 클래스와 테스트 클래스의 FINAL, CREATE OBJECT 없음, 120자 이내
  - 72행 조건은 긍정형이고 빈 IF 분기 없음
  - 주석 처리된 코드나 디버그 문 없음
  - 좁은 DEC 필드 문제 없음: 계수가 decfloat34이고, 결과는 gross 이하라서 p(15,2)를 넘칠 수 없음
  - 테스트가 public 메서드만 호출하고 LOCAL FRIENDS를 쓰지 않음
- **65행 `DATA lv_factor TYPE decfloat34`는 위반이 아니에요.** 인라인 선언으로 바꾸면 계산 타입으로 추론되므로, 정밀도를 위해 명시적으로 타입을 준 것은 정당해요.

**참고 (§8 목록 밖이지만 중요)**
- **54행 (가장 중요):** 전역 클래스의 PUBLIC 메서드가 `RAISING lcx_discount_input`, 즉 로컬 예외를 선언하고 있어요. 실제 클래스 풀이라면 로컬 타입을 public 인터페이스에 쓸 수 없어서 문법 오류가 나고, 클래스 밖의 호출자는 이 예외를 잡을 수도 없을 거예요. 그러면 과제의 "caller can handle" 요건을 충족하지 못해요. 과제가 로컬 선언을 "preferred"라고 했지만, 전역 `ZCX_*`를 쓰는 쪽을 권장해요.
- **47행:** `CLASS-METHODS`(정적 메서드)를 썼어요. clean-code-oop의 "인스턴스 메서드 우선" 규칙에는 어긋나지만, §8 체크 항목에는 들어 있지 않아요.
- **검사기의 `double_space` 9건(24, 44, 49, 58, 93–97행):** 의도적인 열 정렬에서 나온 공백이라 Clean ABAP 기준으로는 결함이 아니에요. 실제로 정렬이 어긋난 곳은 58–60행뿐이에요.
