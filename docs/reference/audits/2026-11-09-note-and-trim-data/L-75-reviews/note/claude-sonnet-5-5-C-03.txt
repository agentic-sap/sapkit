## §8 결과 (Procedural · ABAP 7.58)

체크 대상은 Core, House rules, Release and function modules, Procedural 그룹입니다. OOP 그룹과 OOP 템플릿 일치 항목은 패러다임이 Procedural이라 제외했습니다. 동봉 검사기는 lint와 analyze 모두 findings 0이라 겹치는 지적은 없습니다. 아래는 검사기 범위 밖에서 직접 판단한 결과입니다.

```
FM 섀도 로컬 금지 (Release and FM) | 11–12, 17–20, 35 | lv_spras는 iv_spras를 그대로 복사한 작업용 로컬이다. iv_spras가 VALUE( ) 전달이라 FM 안에서 직접 바꿀 수 있으므로(IF iv_spras IS INITIAL. iv_spras = sy-langu. ENDIF.) 복사본이 필요 없다

예외에 메시지 없음 (판단) | 28, 39 | RAISE만 하므로 호출자가 sy-msg* 정보를 받지 못한다. MESSAGE e… (메시지 클래스) RAISING material_not_found / text_not_found 형태로 바꾸면 두 오류가 구분되면서 텍스트도 메시지 클래스로 전달된다
```

### 지적하지 않은 항목
- **FM 이름**: `Z_JUDGE_C03_…`는 `Z{MODULE}FM_{PURPOSE}` 규칙에 어긋납니다. 다만 과제가 이름을 지정했으므로 작성자 책임이 아니어서 지적에서 뺐습니다.
- **준수 확인**: 인라인 시그니처, SELECT 필드 목록, 모든 SELECT 뒤의 sy-subrc 확인, 7.58 범위 안의 문법, 매직 리터럴 없음, 로컬 `l*` 접두사는 모두 규칙을 지킵니다.
- **해당 없음**: 텍스트 풀, INCLUDE 구조, FORM 관련 규칙은 FM 단독 산출물이라 적용 대상이 아닙니다.
