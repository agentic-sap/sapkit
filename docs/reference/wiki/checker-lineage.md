# 검사기 계보 — 남의 Go 포크를 들였다가 자작으로 갈아탄 이야기

> **이 문서는 재생성 가능한 파생물이다.** 정본은
> [`docs/reference/DECISIONS.md`](../DECISIONS.md)(D-번호 · append-only)와
> [`docs/BLUEPRINT.md`](../../BLUEPRINT.md) §⑵이며, 어긋나면 정본이 이긴다.
> 아래 수치·상태는 **인용된 그 시점의 값**이고 현행이 아니다 — 현행 명령·게이트·판정
> 규칙은 [`CLAUDE.md`](../../../CLAUDE.md)와 `sapkit-cli/`의 자체 문서가 든다.
> **합성 일자 2026-08-25.**

로컬 ABAP 검사기 자리는 이 프로젝트에서 **네 번 성격이 바뀌었다.** 외부 Go 포크(`vsp`)를
트랙 A의 SAP 검증·배포 백엔드로 지목했고(D-001), 편입하지 않기로 한 번 정했다가(D-018)
여드레 만에 뒤집어 레포 안으로 통째 들였고(D-030·D-036·D-037), 제품에는 선택적 로컬
검증기로 동봉했다(D-044). 그다음 실사가 「절차가 잘못된 경로를 보고 있었다」를 드러내며
역할이 오프라인 분석 훅 하나로 좁혀졌고(D-049), 마지막으로 자작 TypeScript 검사기가 그 한
용도를 전부 받아 가며 서브트리 자체가 은퇴했다(D-085). **은퇴가 데려간 것**이 이 페이지의
절반이다 — 구 판정을 다시 뜰 방법이 사라졌고, 그래서 채록본이 「되뜰 수 없는 기준」이 됐다.

---

## 1. 왜 남의 검사기부터 들였나 (2026-07-09 · D-001)

트랙 A(하네스 트랙)의 SAP 검증·배포 백엔드를 **vsp-custom CLI 전용**으로 확정한 것이
출발점이다. 대안이던 MCP 계열은 구조적으로 불가능했다 — 당시 무인 step이
`--strict-mcp-config`로 **MCP 서버를 0개로 기동**했기 때문이다(D-001 기각 사유). vsp의
MCP 모드도 같은 이유로 제외됐다 — **첫 선택은 「그 구조에서 유일하게 돌아가는 것이라서」였다.**

## 2. 편입하지 않기로 한 결정 (2026-07-11 · D-018)

「그러면 소스도 레포로 들일까」의 첫 답은 **아니오**였다. `vsp-custom`은 별도 레포로 두고
`adapters/vsp/`에 **검증 버전 lock**과 부트스트랩 체크·동기 절차만 두기로 했다. 근거는 세
기둥 — ⑴ **소비 형태가 CLI 바이너리뿐**이라 편입의 마찰 해소 이득이 0에 가깝고 ⑵ 상류
`oisee/vibing-steampunk`가 **활발**했으며(별 411 · 오픈 이슈 51 · 2026-06-15 push 실측)
⑶ 트랙 A 미착수라 **수리 이력이 0건**이어서 103k LOC Go(286파일 실측)의 무게부터 지는 것이
순서 역전이었다. 재론 트리거도 걸어 두었다 — 「2-레포 분산 마찰 3회 실증」(D-018).

## 3. 여드레 만의 반전 — 통째 편입 (2026-07-19 · D-030 · D-036 · D-037)

트리거는 발동하지 않았다. 그런데도 D-030이 D-018을 **supersede** 했다. 무너진 것은 세
기둥 중 **「업스트림 결별 비용」** 하나다 — vsp는 이미 로컬 하드포크로 갈라져 있었고
(계보 `v2.38.1-91-g0b03ef2` 위에 로컬 write 게이트·재검증을 얹어 `v2.38.1-94`), 상류와의
실질 동기 경로가 끊겨 **「편입 = 결별」이라는 등식 자체가 성립하지 않았다.** D-030은
재론 트리거가 **불발동인 채로** supersede 했음을 그대로 적었다.

- **범위**(D-036): 소스 **전체**를 편입하되 보증·사용 표면은 **검증 중심**으로 한정한다.
  「검사기만 추출」은 Go 모듈 분할 수술 비용 + **편입분과 외부 잔류분이 두 정본이 되는 표류
  위험** 때문에 기각됐다.
- **실행**(D-037): 원천 HEAD `5a8bedb`의 **git archive 스냅샷**을 최상위 `vsp/`로 펴고
  **히스토리는 이식하지 않았다** — 원 레포의 세션 기록 영역에 비공개 접속 식별 정보가 남아
  있음을 편입 전 실사가 실측했고, 히스토리를 들이면 그것이 새 레포 이력으로 전파된다. 세션
  기록류 **178파일**을 제외해 tracked 745 중 **567**만 들어왔고, 편입된 트리의 잔존 실값은
  **0건**이었다.

## 4. 제품으로 나간 검사기 (2026-07-21 · D-044)

배포 제품에는 「SAP에 던지기 전 로컬에서 잡는」 루프의 반쪽이 비어 있었다. 형태 세 갈래 중
사용자가 **②(동봉 — 릴리스 자산 자동 다운로드)**를 택했고, **③(vsp를 제품 MCP 서버로
병합)은 기각**됐다 — 당시 번들 MCP 서버 **155도구**와 파서·검증 표면이 정면으로 겹치기
때문이다. 바이너리는 git이 아니라 릴리스 자산으로 나갔고 플랫폼 6종의 sha256을 핀 파일에
박았다(D-044 ②③④). **여기서 하나가 빚으로 남았다** — 「릴리스 자산 방식이라 **완전 오프라인
설치는 불가**하고 최초 1회 다운로드가 필요하다」(D-044 정직 유보 ⓑ). 이 빚은 한 달 뒤
D-085가 갚는다. 설치·배포 쪽은 [배포·설치의 변천사](./distribution-install-history.md)가 든다.

## 5. 역할 축소 — 「절차가 잘못된 경로를 보고 있었다」 (2026-07-26 · D-049)

사용자 요청("vsp가 진짜 쓸모가 있는지 확인")으로 돌린 딥 실사가 셋을 실측했다. 절차가
지시하던 **CLI `lint`는 스타일 규칙 6종만** 등록돼 있어 하드코딩 자격증명·루프 내
`COMMIT WORK` 등이 든 probe 파일을 **「No issues found」 exit 0**으로 통과시켰고,
`parse`는 문법 검증기가 아니라 **토크나이저 수준**이었다(비ABAP 쓰레기 입력도 exit 0).
반면 **MCP 모드의 분석 도구는 규칙 13종**을 돌려 같은 probe에서 **10건**을 잡았고, 그것은
`--offline` 플래그로 **SAP 무접속·ADT 무접촉** 기동이 가능했다. 즉 **실체가 있는 쓸모는
오프라인 분석 하나뿐인데 절차는 그 반대편을 보고 있었다.**

그래서 둘이 정해졌다 — ⑴ **R-002 축소**: 「vsp MCP 서버 모드 금지」를 **「온라인(SAP 접속)
MCP 서버 모드 금지」**로 좁힌다(원 근거인 ADT 표면 중복·권한 이원화가 `--offline`에는
성립하지 않는다). ⑵ **훅 자동 배선**: PostToolUse 훅 `offline-code-analysis.mjs`를 신설해
`.abap` 쓰기와 MCP 소스 쓰기의 소스를 검사하고 findings를 모델에 되먹인다 — **경고 전용이고
차단이 아니다**(사용자 기준: "SAP에서 안 도는 것만 차단"). 차단형 훅과 상시 MCP 서버 등록은
함께 기각됐다. 유보도 함께 적혔다 — **오프라인 문법 검증은 여전히 부재** · 훅은 Claude
어댑터 한정 · 13종의 적중률 미측정(D-049).

## 6. 사다리 ⑵가 검사기를 첫 판으로 세운 이유 (2026-08-10 · D-071 → 2026-08-15 · D-084)

renew 다판이 열리며 끝그림이 **「포크 0」**으로 못박혔고 교체 사다리 ⑵에 **검사기 재작성**이
등재됐다(D-071 ④ — 그 판은 등재만 했다). 착수 순서를 정한 것은 D-084다: **⑵는 검증 기준까지
오프라인**(코퍼스 판정 diff 0 · exit code 계약)이라 **SAP 접속 없이 은퇴까지 완주 가능한
유일한 칸**이었고, 그래서 새 판 큐에서 **판1**이 됐다.

## 7. 자작 교체와 서브트리 은퇴 (2026-08-16 · 판1 · D-085)

- **언어·꼴**: TypeScript · 런타임 외부 의존 0 · 새 최상위 `sapkit-cli/`. Go 재작성은 **툴체인이
  레포·CI에 남고 동일 언어 이식은 파생물 위험이 크다**는 이유로, 기존 npm 린터 채용은 **판정이
  달라져 완료 기준 자체가 무너진다**는 이유로 기각됐다.
- **저작 규율**: 참조-재저작 — 구 소스는 **읽기 허용, 복사 금지**. MIT라 법적 의무가
  아니라 **계보 고지를 깨끗이 은퇴시키기 위한 소유권 선택**이었다. **계약 표면은
  승계하고 메시지·설명 문구는 새로 썼다**(D-085 ③).
- **완료 기준**: 판정 동등성 **diff 0**. 커밋 코퍼스 47파일 × 세 표면에서 갈림 0, 광역
  대조(구 내장 샘플 25 + 레포 전체 `.abap` 174)도 갈림 0이었고, **독립 리뷰어가 구 vsp를
  직접 빌드해 기준 파일을 보지 않고 재도출한 결과도 같았다**
  ([RUN-PLAN 브리프 보관소](../run-archive/RUN-PLAN-briefs-2026-08.md) §판1).
- **판정을 조이지 않았다**: 구 구현의 이상 동작을 **그대로 승계**하고 고치는 것은 갈림 장부를
  거친 후속 판의 몫으로 미뤘다. **출력·플랫폼 결함만은** 승계하지 않고 등재했다(D-085 ⑥).
- **빚 청산**: 단일 파일 번들이 `interactive/checker/`로 동봉되며 **설치가 완전 오프라인이
  됐다 — D-044 유보 ⓑ 해소**(D-085 ⑧). 훅은 **파일명과 훅 이벤트를 그대로 둔 채 내부만**
  번들 spawn으로 바꿨다 — 개명하면 기설치 `settings.json`의 참조가 끊기는데 **fail-open이라
  고장이 보이지 않기** 때문이다.
- **은퇴는 검증 뒤 · 별도 커밋**(`bd826187`): `vsp/` **570파일**과 배포 경로·CI의 Go 잡이
  함께 떠났고 상류 고지는 **3 → 2**가 됐다. **가역성이 분리의 이유**였다. **GitHub 릴리스
  자산은 지우지 않았다** — 야생의 구버전 플러그인이 그것을 가리키므로 방치가 곧 하위호환이다
  (D-085 ⑩).

## 8. 은퇴가 데려간 것 — 왜 채록본을 되뜰 수 없나

이것이 이 계보에서 가장 값비싼 대목이다. **은퇴하면 구 vsp도 Go 툴체인도 레포에 없으므로,
「구 vsp가 무엇을 어떻게 판정했는가」를 다시 실행해 확인할 수단이 사라진다.** 그래서 판1은
은퇴 **전에** 구 판정을 파일로 채록했다 — `sapkit-cli/fixtures/baseline/`(47파일 × 세 표면 =
**141칸**)과 `harness/RECORDING.md`가 그 **유일한 잔존 형태**이고, 코퍼스 대조 게이트가 그
기준을 상시 지킨다(D-085 ⑤ · BLUEPRINT §⑵). 되뜰 수 없다는 말의 실제 내용은 셋이다.

- **틀린 값이 들어 있어도 원본과 대조해 발견할 길이 없다.** 채록본은 검증 대상이 아니라
  **검증의 바닥**이 됐다.
- **광역 대조는 다시 못 돌린다** — `RECORDING.md` §9가 그 실측의 유일한 기록이다(D-085 유보
  ⓖ). 상설 게이트가 영영 밟지 못하는 갈래(CRLF·BOM·대용량)도 **1회 실측 기록만** 남았다(ⓐ).
- **계보 하나가 조용히 사라졌다** — 구 포크 안에는 상류 abaplint(MIT)의 기계 번역이 들어
  있었고 그 고지는 Go 파일 헤더에만 있어 `vsp/LICENSE`와 함께 떠났다. 자작 검사기는 abaplint
  유래 **이름**만 계약 표면으로 승계했고(**표현 복제 없음**), 의무가 없음에도 이 사실을 결정
  로그에 남겼다(D-085 유보 ⓕ).

**손이 미끄러지면 은퇴가 통째로 되돌아오는 자리**도 하나 있었다 — `vsp/build/`를 막던 무시
규칙이 `vsp/.gitignore`에 있어 **서브트리와 함께 사라졌고**, 루트 `.gitignore`에 `/vsp/`를
다시 넣지 않았다면 `git add -A` 한 번에 로컬 빌드 산출물이 되살아났을 것이다(독립 리뷰가
잡았다 — [HANDOFF 보관소](../handoff-archive/HANDOFF-archive-2026-08.md) §판5의 「판1에서
승계」 블록). 기설치 바이너리와 그 산출물은 **일부러 건드리지 않았다.**

이 「되뜰 수 없는 기준」이라는 지위는 검사기만의 것이 아니게 된다. 엿새 뒤 구 엔진 포크
`engine/`이 은퇴하며 그쪽 채록본 둘도 **`sapkit-cli/fixtures/baseline/`과 같은 지위**로 명시
등재됐다(D-101 유보 ⓑ). 그 전말은 [엔진 교체의 전 역사](./engine-replacement-history.md)가 든다.

## 9. 도구가 떠나도 규칙에는 구멍이 나지 않는다 (D-085 ⑪)

은퇴할 때 안전 문구를 **삭제하지 않고 일반화**했다. 「vsp `query` 우회 금지」류는 「SAP 행
데이터를 끌어오는 **모든 경로** 금지」로, R-002는 「**SAP 접점을 이원화하지 않는다**」로
넓어졌다 — **금지는 행위에 걸리지 도구 이름에 걸리지 않으므로.** 사라질 파일에만 있던 RV1~RV4
분류·V1~V5 측정표는 삭제 전에 `docs/reference/audits/2026-08-15-rv-classification-record.md`로
한 글자도 고치지 않고 옮겼다. 트랙 A 쪽 맥락은 [트랙 A의 일생](./track-a-lifecycle.md)이 든다.

**남은 것** — 은퇴 시점의 정직 유보 중 자동으로 해소되지 않는 것이 남아 있고(비-UTF-8 원문의
열 밀림 · `check`의 네임스페이스 고객명 취급 · `docs/DESIGN.md` 본문이 아직 구 검사기를 검증
백엔드로 부르는 서술 — D-085 유보 ⓑⓒⓓ · RUN-PLAN 브리프 보관소 §판1 「후속 판이 이어받는
것」), **의도적 차이는 등재하고 등재 없는 차이는 결함이다**라는 규율의 정본은
`sapkit-cli/DIVERGENCES.md`(append-only)다 — 이 페이지는 그 내용을 복제하지 않는다.
